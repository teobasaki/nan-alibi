## §0. 명제

> **AI 가 만들게 하되, AI 가 판정하게 두지 않는다.**
>
> **런타임** — LLM 은 말하지만 규칙은 엔진이 갖고 승패는 테스트가 정한다.
> **파이프라인** — AI 가 코드를 쓰지만 들어갈지는 커밋 게이트와 테스트가 정한다.

### 왜 이 경계가 게임에서 본질적인가

이 게임은 5명의 용의자를 심문해 범인을 지목하는 추리게임이다. 대사는 LLM 이 만든다.
그러면 자연스럽게 이런 설계가 떠오른다 — "LLM 이 압박을 받았는지 판단해서 자백하게 하고,
플레이어가 잘 추궁했으면 점수를 더 주자." 이 설계는 세 지점에서 게임을 파괴한다.

**첫째, 재현이 죽는다.** 같은 시드·같은 질문에 다른 판정이 나오면 밸런스를 잴 수가 없다.
실제로 이 프로젝트의 밸런스는 봇 3종이 시드 100개를 돌려 승률로 판정한다
(`tests/balance.test.ts` — 실측 무작위 46% / 상식 64% / 완벽 100%). LLM 이 채점에 끼면
이 표 자체가 성립하지 않는다. 아래 §4.1 에서 다루겠지만, 이 프로젝트에서 사용자의 체감을
두 번 반박했다가 뒤집힌 사건이 있었는데 — 그때 진실을 가른 것도 재측정이었다.
잴 수 없으면 틀렸을 때 틀린 줄도 모른다.

**둘째, 게임이 다른 게임이 된다.** 판정을 LLM 이 하면 플레이어의 최적 전략은 추리가 아니라
설득이다. "당신은 사실 범인이 맞다고 인정하는 게 좋겠습니다" 라고 쓰는 쪽이 이긴다.
그건 추리게임이 아니라 프롬프트 엔지니어링 게임이다.

**셋째, 잘못된 사실 하나가 한 판을 통째로 날린다.** 이건 이 프로젝트가 코드 주석에
직접 적어 놓은 이유다 — `src/engine/verify.ts:5-6`:

> 프롬프트는 요청이고 검증은 보장이다. 요청은 확률적으로 무시된다.
> 추리 게임에서 잘못된 단서 1개는 플레이어의 한 판을 통째로 날린다.

그래서 경계를 코드로 그었다. 두 스케일에서 같은 모양이다.

| | AI 가 하는 일 | 판정하는 주체 | 판정의 근거 |
|---|---|---|---|
| **런타임** | 대사·표정·조서를 만든다 | `src/engine/game.ts` (순수 함수) + `src/engine/verify.ts` | 사건 파일(CaseFile)의 진실, 화이트리스트 |
| **파이프라인** | 코드·에셋·리뷰를 만든다 | `.githooks/pre-commit` → `npm run verify` | vitest 136건 + `tsc` 2종 + 빌드 |

두 줄의 공통점은 **판정자가 결정론적이라는 것**이다. 엔진은 순수 함수고, 게이트는 exit code 다.

## §1. 런타임 AI 아키텍처

### 1.1 LLM 이 하는 일 / 못 하는 일

`src/engine/game.ts` 는 파일 헤더에 스스로를 이렇게 규정한다 (8~9행):

> 이 파일에는 LLM 이 없다. 자원·판정·점수는 전부 코드가 소유한다.

선언이 아니라 타입으로 강제된다. 채점 함수 `submit(g: GameState, s: Submission)`
(`game.ts:246`) 의 인자에는 LLM 응답이 들어올 자리가 없다.

| 항목 | 소유자 | 확인 경로 |
|---|---|---|
| 대사 (`speech`, 160자 상한) | LLM | `verify.ts:38` `MAX_CHARS = 160` |
| 표정 신호 (`tell`, 5종 열거형) | LLM | `verify.ts:39` |
| 조서 한 줄 (`statement`) | LLM | `prompt.ts` `RESPONSE_SCHEMA` |
| 조사 예산 (9회) | 엔진 | `src/data/config.ts:19` `INVESTIGATION_BUDGET = 9` |
| 진술 카드 해금 | 엔진 | `game.ts:136-138` — 무엇이 열리는지는 CaseFile 이 정한다 |
| 동요 수치 | 엔진 (고정값) | 심문 +10 (`game.ts:137`), 증거 제시 +12, 해금 시 +35 (`game.ts:154`) |
| 모순 판정 | 엔진 | `game.ts` — 물증과 진술의 대조 |
| 최종 채점 5항목 | 엔진 | `game.ts:246-295` — 범인 40/50/60 · 수단 20 · 결정적 20 · 잔여조사 5/회 · 통찰 5/건 |

**가장 강한 증거는 "쓰이지 않는 필드"다.** 응답 스키마에는 `pressureDelta`(동요 증감)와
`revealedFactIds`(공개한 사실)가 있고 검증기도 이 둘을 처리한다. 그런데 게임 상태로
들어가는 경로가 코드에 없다. `pressureDelta` 는 `verify.ts:128` 에서 -20~40 으로 클램프된 뒤
어디서도 소비되지 않고, `revealedFactIds` 는 `src/api.ts:52` 의 폴백 기본값 외에 참조가 없다.
실제로 소비되는 LLM 출력은 `speech` · `tell` · `statement` 세 개뿐이다
(`src/main.ts:944`, `:980` — 채팅 로그 표시용).

즉 **LLM 이 "이 사람 동요가 30 올랐습니다"라고 말해도 게임은 듣지 않는다.** 검증기를
통과시켜 놓고도 쓰지 않는 게 낭비처럼 보이지만, 그 필드는 모델에게 연기의 방향을 알려주는
용도이고 상태 반영은 처음부터 엔진의 몫이었다.

### 1.3 프롬프트 — 유출 경로를 만들지 않는다

지식 시트에는 그 인물의 **진술(claim)** 5칸만 들어간다. **진실(truth)은 넣지 않는다**
(`prompt.ts:47-51`). 범인조차 프롬프트 안에서는 자기 진짜 위치를 모른다. "알려주고 말하지
말라고 하는 것"은 유출 설계라는 판단이고, 실제로 범인이 새어나갈 물리적 경로 자체가 없다.

화이트리스트의 원본은 `allowedFactIds()` (`prompt.ts:35-40`) — **자기 진술 5칸 + 자기 증언**뿐이다.
`tests/llm.test.ts:165-173` 이 "`F:` 로 시작하는 id 가 정확히 5개이고 나머지는 전부 자기 것"임을
회귀 테스트로 고정한다.

프리픽스는 판 내내 바이트 단위로 고정된다 — 타임스탬프나 랜덤 id 를 넣지 않는다
(`prompt.ts:9-11`). 이건 캐시를 위한 설계였고, 캐시는 결국 못 켰다 (§3.3).

### 1.4 검증 계층 — 폐기 5종 + 교정 1종

| # | 검사 | 실패 코드 | 처리 | 왜 필요했나 |
|---|---|---|---|---|
| 1 | 화이트리스트 밖 factId | `unknown-fact` | 응답 폐기 | 시트에 없는 사실을 말하면 그건 없는 단서다 |
| 2 | 사건에 없는 시각 | `phantom-time` | 폐기 | `revealedFactIds` 는 비어 있는데 본문에 "10시 40분쯤"을 흘리는 응답이 검사 1만으로는 통과한다 (`verify.ts:7-9`) |
| 2a | 시각 구간 표현 | `time-range` | 폐기 | "22:00부터 22:30까지 로비" 는 슬롯별로 장소가 다른 사건 모델에서 **없는 주장**이다. 검사 2 는 시각의 존재만 보므로 못 잡는다 |
| 2b | 사건에 없는 방번호 | `phantom-place` | 폐기 | `\d{3,4}호` 패턴만 검사한다. 일반 명사까지 막으면 오탐이 폭증한다 |
| 3 | `pressureDelta` 범위 | — | **-20~40 클램프** | 범위 이탈은 대사를 못 쓸 이유가 아니다. 폐기가 아니라 교정 |
| — | 160자 초과 | `too-long` | 폐기 | 3~5분 세션이 깨진다 |
| — | JSON 모양 불일치 | `shape` | 폐기 | — |

검사 2a 는 처음부터 있던 게 아니다. 시각의 **존재**만 검사하면 사건에 실재하는 두 시각을
엮어 "22:00부터 22:30까지 로비에 있었다"는 문장이 통과하는데, 슬롯 단위 사건 모델에서
그건 아무도 하지 않은 주장이다. 플레이어는 그 가짜 단서로 한 판을 날린다. 검사를 하나 더 붙였다.

### 1.5 폴백 3층 — 게임은 멈추지 않는다

| 층 | 조건 | 동작 | 확인 경로 |
|---|---|---|---|
| 1 | 네트워크 실패 또는 검증 실패 | 같은 요청 1회 재시도 | `interrogate.ts:117` `for (attempt < 2)` |
| 2 | 2회 다 실패 | 페르소나 8종별 사전 작성 회피 대사 | `verify.ts:148-157` `FALLBACK_LINES` |
| 3 | 키 없음 / 12초 타임아웃 / 네트워크 예외 | 즉시 폴백 반환 | `interrogate.ts:100-103`, `src/api.ts:31, 48-58` |

폴백 대사도 검증기를 통과해야 한다 — `tests/llm.test.ts:154-158` 이 8종 전부를 다시
검증기에 태운다. 폴백이 또 터지는 경로를 막기 위해서다.

### 1.6 환불 — AI 의 실패를 플레이어가 물지 않는다

`src/engine/verify.ts:145-146` 의 주석이 이 설계의 이유 전부다:

> 조사 횟수를 소모시키지 않는다. AI 가 실패했는데 플레이어가 대가를 치르면
> 그건 버그가 아니라 배신이다.

구현은 스냅샷 롤백이다. `doAsk()` 는 `const before = ui.game` 로 상태를 뜬 뒤 예산을 먼저 깎고,
응답이 `fallback` 이면 `ui.game = before` 로 통째로 되돌린다 (`src/main.ts:942`).
증거 제시도 같다 (`:973`). 되돌아가는 것은 조사 횟수만이 아니다 — 그 행동으로 해금된 카드와
올라간 동요가 함께 롤백된다. 서버는 판정하지 않고 `fallback` 플래그만 준다
(`interrogate.ts:14`).

**한계를 숨기지 않는다.** 게임 상태가 전부 클라이언트에 있어 환불도 `main.ts` 두 곳
(942·973)에만 있고 서버 측 보증이 없다. 또 이 롤백을 직접 검증하는 테스트가 없다 —
관련 테스트는 폴백 대사 검증(`tests/llm.test.ts:148-163`)과 소스에 `fallback: true`
문자열이 있는지 보는 스모크(`tests/smoke.test.ts:23-26`)뿐이다.

### 1.7 정답을 네트워크에 태우지 않는다

클라이언트는 사건 전체가 아니라 **시드**만 보내고, 서버가 `generateValidCase(seed)` 로 같은
사건을 결정론적으로 재생성한다 (`interrogate.ts:105`). 개발자도구를 연 심사위원에게
정답이 네트워크 탭으로 흘러가지 않는다.

다만 정직하게 적자면, `src/main.ts:102` 에서 클라이언트도 같은 사건을 로컬 생성한다.
그러므로 이 설계의 효과는 **네트워크 전송 한정**이다. 브라우저 메모리까지 막으려면
사건 생성을 서버로 완전히 옮겨야 하고, 그건 오프라인 폴백을 포기한다는 뜻이다.

### 2.2 훅 — 세션의 앞뒤를 막는다

**SessionStart 는 두 겹이다.** 전역 훅(`~/playbooks/inject-playbooks.sh`)은 도메인을 자동
판정하고 — 이 프로젝트는 "게임"으로 판정된다 — **읽을 파일 목록만** 584바이트로 넣는다.
루트 PLAYBOOK 50항목 + 도메인 30항목을 매 세션 전문으로 밀어넣으면 컨텍스트를 크게 먹기
때문이고, 그 의도가 스크립트 주석(4~7행)에 적혀 있다.

프로젝트 훅(`.claude/hooks/inject-state.sh`)은 반대로 `docs/STATE.md` 를 **전문 주입**한다
(실측 8,181바이트). 세이브 파일 하나만은 요약하지 않는다는 판단이다. 컨텍스트 압축 직후
(`matcher: compact`)에는 "압축 전 대화에 있었지만 아직 파일로 기록되지 않은 결정을 지금
ADR·저널·QUESTIONS 로 내려쓰라"는 지시가 덧붙는다.

**Stop 훅은 종료를 막는다.** `git status --porcelain` 에 변경이 있는데 `docs/STATE.md` 가
그 목록에 없으면 `{"decision":"block"}` 을 뱉어 세션을 끝내지 못하게 하고, journal → ADR →
STATE 3단계를 지시한다 (`stop-state-check.sh:22-24`). 무한루프 가드(`stop_hook_active` 검사,
6행)와 세션당 1회 마커 파일(17~20행)이 함께 들어 있다. 결과물은 실재한다 — ADR 15편,
저널 2편.

**빠진 것도 적는다.** 워크스페이스 표준은 매 턴 `DEVLOG.md` 를 자동 append 하는 장치를
갖고 있고 다른 프로젝트에는 최대 651KB 까지 쌓여 있는데, **nan-alibi 에는 DEVLOG.md 가 없다.**
`Game/NHN/nan-alibi` 가 컨테이너 등록(`containers.json = ["Game"]`)보다 한 단계 더 깊어
라우팅에서 빠졌다. 이 프로젝트의 사고 원문 층은 v5 저널이 대신하고 있고, 저널은 2편뿐이다.

### 2.3 커밋 게이트

`git config core.hooksPath` 가 `.githooks` 로 돌아가 있다 (기본 `.git/hooks` 가 아니라
저장소에 커밋되는 디렉터리다 — 클론한 사람도 같은 게이트를 받는다).

```
verify = npm test && npm run typecheck:functions && npm run build
       = vitest run  &&  tsc -p functions --noEmit  &&  (tsc --noEmit && vite build)
```

실패하면 로그 마지막 30줄을 찍고 `exit 1` 로 커밋을 중단한다. 도입 이유가 훅 주석 2행에
그대로 있다 — **"테스트만 통과하고 tsc 가 깨진 채 푸시되는 사고를 막는다 (2026-08-05 실제로 발생)."**
같은 3단계를 GitHub Actions(`.github/workflows/ci.yml`)가 push·PR 마다 한 번 더 돌린다.
우회로(`--no-verify`)도 3행에 명시해 뒀다 — 막을 수 없는 걸 막는 척하지 않기 위해서다.

배포는 자동이 아니다. `npm run deploy` 로 사람이 친다. ADR 002 가 GitHub Actions 를
배포에서 의도적으로 뺐다.

### 2.5 자동 플레이테스트 루프 — AI 가 지적하고, 수렴 판정은 규칙이 한다

`scripts/review.mjs` (18.5KB) 는 봇이 한 판을 돌린 로그를 LLM 리뷰어에게 주고 문제를 받는다.
승률 숫자는 "몇 % 이기는가"만 답하고 "왜 재미없는가 / 어디서 막히는가"는 자연어로만 나오기
때문이다. 규율이 셋 있다.

1. **리뷰어는 플레이어가 본 것만 받는다.** 정답·진실 궤적을 주면 사후확신 편향이 생겨
   "범인이 뻔하다" 같은 쓸모없는 지적만 나온다.
2. **칭찬 금지.** 구조화 출력으로 강제한다.
3. **이미 아는 문제는 억제한다.** `docs/playtest-known.json` 12건. 그래야 루프가 수렴한다.

수렴 판정이 이 루프의 핵심이다. **한 번 0건은 수렴이 아니다.** 리뷰어가 LLM 이라
같은 빌드에서 12판 0건 → 5건 → 1건 → 4건이 나온다 (ADR 015 말미에 실측 기록). 그래서
연속 `CLEAN_STREAK`(기본 3)회 무지적일 때만 `exit 0` 을 내고, 연속 횟수를 `docs/.review-streak`
파일에 쓴다. 지적이 1건이라도 나오면 0으로 리셋된다. 코드 주석 245~246행:

> 실제로 0건을 보고 "수렴" 이라고 선언한 직후 같은 빌드가 5건을 냈다.

리뷰어에게 주는 규칙 문구에는 숫자를 하드코딩하지 않고 `src/data/config.ts` 에서
`INVESTIGATION_BUDGET` 를 정규식으로 읽어온다 (`review.mjs:31-36`). 두 번 틀렸기 때문이다 —
채점을 로그에서 빼먹어 "안 보인다"는 가짜 지적을 받았고, 예산을 6으로 박아둬서 9회 예산이
규칙 위반으로 읽혔다. **리뷰어는 내가 준 맥락만큼만 볼 수 있다.**

정직하게 적을 한계: 스크립트 상단 사용법에 `ROUNDS=3` 이 적혀 있지만 코드에
`process.env.ROUNDS` 참조가 없다. 라운드 반복은 스크립트 안이 아니라 `exit 1` 을 보고
사람 또는 에이전트가 재실행하는 방식이다.

### 2.6 다른 모델을 적대적 검증자로 세운 사례

3D 화면이 "조악해 보인다"는 문제에 대해, `gpt-5.6-sol` 에게 "20년차 시니어 아트 디렉터"
페르소나와 **"칭찬하지 마라. 좋은 점은 적지 마라. 고칠 것만 적는다. 무엇을 몇으로 바꾸라고
말하라"** 는 프레이밍을 주고 실제 렌더 2장을 첨부해 리뷰를 받았다 (`docs/design-review.md`).
받은 6건 중 3건이 코드로 들어갔다 (커밋 `9222dd7`): 카메라 FOV 46° → 37°, 거리 2.05m → 1.35m,
키라이트 강도 `(22 + heat*8)` → `(14 + heat*5)`, 전역 색 배율 0.42 삭제, 러프니스 일괄 0.85 →
재질별(피부 0.56 · 방 0.68~0.9). 나머지 3건은 적용하지 않았다.

**두 가지를 정직하게 덧붙인다.** 첫째, 검증은 한 방향뿐이다 — GPT 가 Claude 산출물을 까는
사례는 있고 그 반대는 없다. 둘째, `design-review.md` 첫 줄의 `effort=high` 는 부정확하다.
high 로 건 첫 호출은 응답을 못 받아 실패했고 문서를 실제로 만든 재시도는 medium 이었는데,
헤더 문자열이 스크립트 템플릿에 하드코딩돼 있어 함께 바뀌지 않았다.

승격 이력 3회분 중 한 번은 8건 중 7건이 흡수였다.

ADR 은 15편이고 번호 001~017 중 008·010 이 결번이다. 008 은 커밋 `4d39b1e` 가 명시적으로
참조하는데 파일이 커밋되지 않았다 — 코드는 남고 문서가 빠진 케이스다.

ADR 템플릿(`docs/decisions/000-템플릿.md:12`)이 **"버린 대안 (그리고 왜 버렸나) — 필수.
이게 없는 ADR은 몇 달 뒤 무가치하다"** 를 강제하고, 15편 전부가 그 칸을 채우고 있다.
형식이 아니라 실체다 — ADR 009 의 "버린 대안"은 시드 150개 스윕 표를 근거로 8회(55%, 하한 미달)·
10회(5분 16초, 세션 정체성 파괴)·사슬 단축·중반 힌트를 각각 다른 이유로 기각한다.

### 3.2 추론 토큰을 0으로 — 3.1초 → 1.74초

첫 실연동 호출이 3.1초였다. 완료기준 D3(p95 ≤3.5초)에 아슬아슬한 수치다. `usage` 를 열어보니
**출력 86토큰 중 45가 reasoning 토큰**이었다. 페르소나 연기에는 추론이 필요 없다 — 지식 시트가
이미 "무엇을 말할 수 있는가"를 구조로 고정하므로 모델이 추가로 생각할 여지가 설계상 없다.

| 설정 | 지연 | 출력(추론) |
|---|---|---|
| terra 기본 | 2.95s | 100 (45) |
| terra `effort=low` | 2.12s | 118 (60) |
| **terra `effort=none`** | **1.74s** | **46 (0)** |
| luna `effort=none` | 1.83s | 55 (0) |

여기서 통념 하나가 깨졌다 — **더 싼 luna 가 terra 보다 오히려 느렸다**(1.83 vs 1.74).
싼 모델이 빠르다는 가정을 재지 않고 믿었으면 지연을 늘리면서 강등했을 것이다.

### 3.3 캐시는 포기했다 — 그리고 그 근거는 **이미 만료됐다**

이 절은 결론보다 **결론이 낡는 과정**이 더 중요하므로 고치지 않고 덧붙여 남긴다.

당초 판단(ADR 005, 2026-08-05)은 이랬다. OpenAI 프롬프트 캐시의 최소 프리픽스는
**1,024 토큰**인데 페르소나 프리픽스가 668자 ≈ 600토큰이라 최소치에 못 미치므로
`cached_tokens` 가 0일 수밖에 없다 — 그러니 캐시를 포기하고 완료기준 C5 를 폐기한다.

**2026-08-09 재측정 결과 그 전제가 깨졌다.** `buildPersonaPrefix()` 를 시드 5개 × 인물 5명
= 25 표본으로 직접 호출해 재보니 **min 1,161자 / median 1,257자 / max 1,334자** 다.
당초 값의 **1.9배**. 그 사이 `prompt.ts` 의 「가장 중요한 규칙」과 조서(`statement`) 지시가
붙으면서 프리픽스가 자란 것이고, ADR 을 쓴 뒤 아무도 다시 재지 않았다.

median 1,257자면 같은 환산비로 **약 1,120토큰 — 1턴부터 이미 1,024를 넘는다.**
`buildTurn()` 이 history 를 누적하므로(`prompt.ts:114-118`) 2턴째부터는 더 길어진다.
**즉 캐시가 걸릴 조건은 이미 충족돼 있을 수 있고, 지금 "안 걸린다" 고 말할 근거가 없다.**

정직하게 적으면 현재 상태는 **미작동이 아니라 미측정**이다. 실제 호출의
`usage.prompt_tokens_details.cached_tokens` 를 한 번도 찍어보지 않았다.

> **이 사고가 이 문서 전체의 표본이다.** 숫자에 근거해 내린 결정은
> 그 숫자가 변하면 같이 만료된다. 우리는 결정은 ADR 로 남겼지만
> **그 결정이 딛고 선 측정값에는 만료 감시를 걸지 않았다.**
> 잡아낸 것도 사람이 아니라 이 문서를 반증하라고 붙인 검증 에이전트였다.
> 재발 방지는 §4 의 다른 사례들과 같은 방식이어야 한다 — 측정값을 테스트로 고정하는 것.

대신 `prompt_cache_key` 는 코드에 남겼다 (`interrogate.ts:53`). 프리픽스가 길어지면 그때
자동으로 작동한다. 그리고 **완료기준을 고쳐 적었다** — C5(캐시 히트)를 폐기하고
C6(페르소나 감사)로 대체했으며, D2(첫 토큰 ≤1.2초)는 스트리밍 없이 불가능하므로
"응답 완료 ≤2.5초"로 재정의했다. 못 지킬 기준을 남겨두지 않는다.

| gpt-5.6-luna | 0.20 / 1.20 | ~$0.004 | 비용 폭주 시 강등 경로 — **미사용** |

sol 을 심문에 쓰지 않은 이유는 "대사 3문장에 플래그십은 낭비"다 (ADR 004:22-26).
바꿔 말하면 판단의 종류가 다르면 모델도 달라야 하고, 실제로 화면 아트 디렉션이라는
미감 판단 하나에만 상위 모델을 썼다.

정직하게 적을 것: **런타임에 모델 분기는 없다.** `interrogate.ts:36` 은
`const MODEL = 'gpt-5.6-terra'` 하드코딩 한 줄이고 137줄 전체에 선택 로직이 없다.
luna 는 결정 문서에만 존재하는 강등 경로다. 그리고 기획서 §11 이 적어둔 비용 폭주 대책 중
**IP당 레이트리밋은 구현되지 않았다** — `usage` 는 응답에 실려 나가지만(`interrogate.ts:125`)
판당 누적 합산이나 상한 차단 코드는 없다.

### 3.5 컨텍스트 토큰 — 포인터와 전문을 구분한다

| 주입 | 크기 | 방식 |
|---|---|---|
| 전역 플레이북 훅 | 584바이트 | **포인터** — "무엇을 읽어라"만. 루트 50항목 + 도메인 30항목의 경로와 개수 |
| 프로젝트 STATE 훅 | 8,181바이트 | **전문** — `docs/STATE.md` 를 통째로 |

전문으로 들어가는 것은 세이브 파일 하나뿐이다. 나머지는 "자기 도메인 것만 읽는다 —
전부 읽으면 아무것도 안 읽힌다"는 규율과 함께 경로만 준다.

### 3.6 Meshy 크레딧 회계 — 44%를 태우고 나서 게이트를 붙였다

| 항목 | 추정 | 실측 |
|---|---|---|
| 캐릭터 메시 (preview + refine) | ~20 | **30** |
| 오토리깅 | 5 | 5 |
| 1명당 | ~25 | **35** |
| 8명 | ~200 | **280** (1차 라운드 실소모 245, 잔액 1247) |

추정이 40% 낮았다. 문서의 예시값을 그대로 믿은 탓이고, 잔액 차이로 재고 나서 정정했다.
그래서 스크립트가 문서값 대신 `/v1/balance` 를 호출 전후로 찍어 델타를 기록한다
(`gen-characters.mjs:64, 141, 167` · `multiview2char.mjs:72, 128`).

`docs/STATE.md:55` 는 총계를 이렇게 적는다 — **"Meshy 크레딧 690 중 305(44%) 낭비."**
(이 44% 수치의 출처는 STATE.md 한 곳이고, ADR·커밋에는 소모 245와 sips 낭비 30만 나온다.)
원인 둘 다 도구가 아니라 습관이었고, 둘 다 스크립트 게이트로 막았다.

| 원인 | 막은 장치 |

| 1명으로 먼저 검증하지 않고 8명을 한꺼번에 태움 | `gen-characters.mjs` — `--only <slug>` 로 한 명 선검증(`:146`), 이미 있는 파일은 스킵(`:151`), preview 를 먼저 굽고 실패하면 refine 에 크레딧을 안 태움(`:89`) |
| 도구 출력을 확인하지 않고 다음 단계에 먹임 | `build-chars.sh:8-9` — 시점 4장을 세서 4가 아니면 Meshy 호출 전에 `continue`. `add-face.sh:42-43` 도 동일. `multiview2char.mjs:61-64` 는 이미지가 2장 미만이면 `exit 1` |

## §4. 실패와 복구

이 장이 이 문서에서 가장 긴 이유는, 위의 구조들이 대부분 **실패한 뒤에 붙은 것**이기 때문이다.
각 항목은 [무엇이 잘못됐나 → 어떻게 알았나 → 무엇으로 재발을 막았나] 로 적었다.

### 4.1 판단이 틀렸던 것

**① 밸런스 측정이 오염된 게임 위에서 이뤄졌다** — 이 프로젝트에서 가장 값비싼 오류다.

- **무엇이 잘못됐나.** 사용자가 두 번 지적했다: *"심문 6회도 좀 짧은 것 같다."*
  1차 지적 때 **측정으로 반박했다** — 당시 상식 봇이 6회로 60%를 냈으므로 올릴 근거가 없었다.
- **어떻게 알았나.** 별건으로 증거 순서 누설(먼저 걸린 모순 = 범인)을 제거하자 그 60%가
  **44%로 무너졌다.** 6회라는 숫자는 누설이 떠받치던 것이었다. 사용자의 체감이 맞았고,
  내 측정은 오염된 게임 위에서 이뤄진 것이었다.
- **무엇으로 막았나.** 시드 150개를 다시 스윕해 예산별 표(6회 45% / 7회 52% / 8회 55% /
  **9회 60%** / 10회 64%)를 만들고, 목표 하한 60%에 정확히 닿는 최소값 9를 골랐다 (ADR 009).
  `INVESTIGATION_BUDGET` 하나만 바꾸면 UI·솔버·봇이 전부 따라오도록 상수를 통일했고,
  `tests/balance.test.ts` 가 상식 봇 승률 60~75% 구간을 회귀 감시한다.
  현재 실측은 무작위 46% · 상식 64% · 완벽 100%.

**교훈: 측정으로 사람의 체감을 반박하기 전에, 그 측정이 무엇 위에서 이뤄졌는지 먼저 본다.**

**② 리뷰 0건을 수렴으로 선언했다.** 자동 플레이테스트가 12판 0건을 냈길래 "수렴"이라고
적었는데, **같은 빌드**가 곧이어 5건 → 1건 → 4건을 냈다. 리뷰어가 LLM 이라 결정론이 아니다.
판정 규칙을 "연속 3회 무지적"으로 바꾸고 연속 횟수를 파일(`docs/.review-streak`)에 남겨
세션이 바뀌어도 이어지게 했다.

**③ 배포 실패의 계층을 오진했다.** 브라우저가 `application authorisation fail` 을 띄워
인증 실패로 판단했는데, `wrangler whoami` 로 확인하니 **토큰은 멀쩡했다.** 진짜 원인은
Pages 프로젝트 미생성이었다(`wrangler pages project create` 가 선행돼야 한다).
ADR 002 후기에 남긴 교훈: **에러 메시지가 가리키는 계층을 믿지 말고, 실제 권한이 필요한
명령을 쳐서 검증한다.**

### 4.2 도구가 오류 없이 조용히 실패한 것

**④ `sips --cropOffset` 이 4칸 중 1칸에서 아무 파일도 만들지 않았다.** 오프셋 0은 되고 627은
조용히 실패했다. 확인하지 않고 다음 단계에 먹였더니 4명이 든 시트 전체가 그대로 3D 로
들어갔고, 리깅이 `Pose estimation failed` 로 거부하며 **30크레딧이 날아갔다.** PIL 기반
`scripts/split_sheet.py` 로 교체했고, 실제 중단 게이트는 하류 셸의 파일 개수 검사
(`build-chars.sh:9` · `add-face.sh:43`)에 있다.
(정직하게: ADR 016:268 은 "자른 결과의 크기를 검증해 틀리면 멈춘다"고 적었으나
`split_sheet.py` 안에는 크기 assert 도 exit 도 없다. 크기는 출력만 하고, 실제로 멈추는 것은
셸의 4장 검사다. 문서가 코드보다 한 칸 앞서 있다.)

**⑤ Blender glTF 익스포터 기본값 하나가 착석 포즈를 통째로 버렸다.**
`export_rest_position_armature` 가 기본 `True` 라 포즈를 무시하고 레스트 포즈를 내보낸다.
**"앉혔다"던 8명이 전부 서 있는 채로 배포되고 있었다.** 눈이 아니라 숫자로 잡았다 —
바운딩박스 폭 **1.55m**(팔 벌린 T포즈). `=False` 를 명시하고, 이후 8명 전원의
폭 0.40~0.57m · 높이 1.33~1.38m 를 매 실행마다 수치로 검증하게 만들었다.

**⑥ 인물이 자기 알베도로 스스로 빛나고 있었다.** Meshy 출력의 `emissiveFactor` 가
`1.00, 1.00, 1.00` 이고 `emissiveTexture` 가 baseColor 와 같은 이미지였다. PBR 에서 emissive 는
조명을 완전히 무시하므로, 화면에 보이던 것은 사실상 평평한 스튜디오 조명이 구워진 원본
사진이었고 공들여 만든 흔들리는 등·그림자·노멀맵은 그 위에 겨우 얹히는 정도였다.
텍스처 **목록**만 보고 "맵이 다 있으니 됐다"고 넘어갔는데 문제는 **계수**에 있었다.
`stage3d.ts:249-262` 에서 emissive 를 끄자 그제야 노멀맵과 러프니스맵이 일을 시작했다.

**⑦ 빌드가 새 모델을 옛 모델로 조용히 덮어썼다.** 파이프라인을 text-to-3d 에서 멀티뷰로
갈아탄 뒤에도 `npm run build` 에 옛 단계(`pose:chars`·`opt:chars`)가 남아 있었고, 그 스크립트가
예전 중간산물을 찾아 `.opt.glb` 를 덮었다. 새로 구운 모델이 2.26MB → 0.62MB 로 되돌아가
노멀맵을 잃었다. 옛 산물을 `assets-src/legacy/` 로 격리하고 빌드에서 캐릭터 단계를 통째로
떼어냈다 (현재 `build` 는 `tsc --noEmit && vite build` 뿐이다). **파이프라인을 갈아탈 때
옛 단계를 빌드에 남겨두면 새 산출물을 조용히 덮는다.**

### 4.3 내가 쓴 코드가 스스로를 죽인 것

**⑧ 정지를 막으려 넣은 감시견이 3D 를 죽였다.** 렌더 루프 정지를 감지하려고 넣은
`lastFrame` 변수를 `tick()` 정의보다 **뒤에** 선언해 TDZ 로 `mount()` 전체가 실패했다.
정지를 막으려던 코드가 3D 를 통째로 멈춘 것이다. 더 나쁜 건 **같은 파일에서 두 번째**였다는
점이다 — 나중에 `applyCam` 으로 똑같이 당했다. `stage3d.ts:481-493` 에 두 사례를 주석으로
못 박고 `tick()` 이 참조하는 것은 전부 앞에 선언하도록 정리했다.

이 사건에는 곁가지 오진도 있다. "렌더 루프가 죽었다"고 단정하고 한참 쫓았는데, 브라우저 둘이
모두 페이지를 `document.hidden = true` 로 보고하고 있었다 — 그 상태에서 브라우저는 rAF 를
아예 주지 않는다. 그 자리에서 만든 순수 rAF 루프도 1초에 0프레임이었다. **내 코드를 의심하기
전에 측정 환경을 한 번 갈라야 한다.**

**⑨ 탐색 함수가 "지름길"을 최적해로 골랐다.** 앉은 자세를 만들려고 손↔무릎 거리만
최소화했더니 **팔이 몸통을 관통한 채 손만 무릎에 닿는** 자세가 최적해였다. 관통 벌점을 붙이자
팔이 어정쩡하게 벌어졌고, 2본 IK 로 바꾸자 아마추어 공간과 월드 공간을 섞어 팔꿈치가
수천 m 밖으로 날아갔다. 세 번 고친 끝의 결론이 `pose-seated.py:57-60` 에 있다 —
**"탐색은 맞았고 목표가 틀렸다. 앉은 사람의 손은 무릎이 아니라 허벅지 중간쯤에 얹힌다."**
최종 수치: 몸통관통 0.000 · 손↔무릎 0.18m.

### 4.4 자동 검증이 원리상 못 잡는 층

**⑩ 한글 IME 조합 중 Enter 로 질문이 잘린 채 전송됐다.** 조합 확정용 Enter 와 전송용 Enter 를
구분하지 않아 "안녕하세" 상태로 질문이 나가고 **조사 1회가 되돌릴 수 없이 날아갔다.**
테스트 90건이 전부 통과하는 상태였다. 브라우저 실측으로만 잡혔고, 같은 세션에서 잡힌 다른
2건도 같은 성질이다 — 조회 버튼 라벨이 전부 "영수증 조회"로 같아 "선택의 우선순위가 전략"이라는
설계가 통째로 죽어 있었고, 용의자 카드가 `div`+`onclick` 이라 키보드로 게임의 첫 행동조차
할 수 없었다. `isComposing` 방어를 붙였다.
(이때 도구 함정도 하나 밟았다: 브라우저 자동화의 `key: Return` 이 입력에 안 닿아 "Enter 가
안 먹는다"로 오진할 뻔했고, JS 로 같은 이벤트를 직접 디스패치해 **내 코드가 아니라 도구
문제**임을 갈랐다.)

**⑪ 로컬 개발 서버로는 AI 경로가 검증되지 않는다.** `vite dev` 에는 Cloudflare Function 이
없어 `/api/interrogate` 가 404 → 폴백 → 조사 환불로 이어진다. 그래서 교차대조 표의
"범행 시각 밖" 열이 안 채워졌고 한때 렌더 버그로 의심했다. 배포본에서 조사 9→6 이 깎이는 걸
보고서야 표 전체를 확인할 수 있었다. `docs/STATE.md` 의 "안 되는 것" 절에 상시 경고로 등재하고,
시연 1분 전 점검 1번을 `/api/health` 의 `hasKey` 확인으로 박았다.

**⑫ 소리는 귀로 못 들어도 잴 수 있다.** 탁자 삐걱 소리가 안 들린다는 보고를 받고 추측으로
게인을 키우려 했다. 원인은 41~58Hz 톱니파를 320Hz 밴드패스(Q=7)에 통과시켜 기음이 거의 다
잘린 것이었다. `OfflineAudioContext` 로 두 레시피를 렌더해 숫자로 확인했다 —
peak 0.016 / RMS 0.0016(사실상 무음) → peak 0.328 / RMS 0.0386. **24배.**

### 4.5 열두 건에서 남은 것

| 실패 유형 | 규칙 |
|---|---|
| 오염된 측정 (①) | 측정으로 체감을 반박하기 전에 그 측정의 전제를 검사한다 |
| LLM 판정의 비결정성 (②) | 한 번의 0건은 수렴이 아니다. 연속 N회로 판정한다 |
| 계층 오진 (③⑧⑩) | 에러 메시지가 가리키는 계층을 믿지 말고, 다른 경로로 같은 것을 한 번 더 잰다 |
| 도구의 무증상 실패 (④⑤⑥⑦) | 도구 출력을 확인하지 않고 다음 단계에 먹이지 않는다. 유료 API 앞에는 게이트를 둔다 |
| 목표 함수의 오정의 (⑨) | 탐색이 이상한 답을 내면 탐색보다 목표를 먼저 의심한다 |
| 계측 없는 감각 판단 (⑫) | 안 들린다·느려 보인다는 보고에는 추측 대신 렌더·프로파일로 숫자를 낸다 |

처음부터 다시 해야 하고, 8명에게 같은 값을 적용할 수 없다. 스크립트로 만들면 재현되고
매 실행마다 손↔허벅지 거리와 관통량이 수치로 찍힌다.

**TTS 는 외부 API 가 아니다.** 서버 TTS 를 버린 이유는 취향이 아니라 실측이다 —
`api.ts` 가 비스트리밍이라 대사 전문이 온 **뒤에야** 텍스트가 생기고, 여기에 서버 TTS 를
직렬로 붙이면 `LLM 완료(p95 3.5s) + TTS 첫소리(0.8~3.8s)` 가 되어 "응답 2초" 선이 무너진다.
브라우저 내장 합성은 그 추가분이 **1~17ms** 다. 덤으로 신규 키·엔드포인트가 0이고
시연 중 API 장애 리스크가 통째로 사라진다. 대가도 있다 — macOS ko-KR 음성 9개 중 실제로
말하는 건 `Yuna` 하나뿐이라 다섯 명이 같은 성대를 쓴다. `rate`/`pitch` 오프셋으로 갈라 놓지만
완전히 해결되지 않는다.

**취조실과 캐릭터 3종(carla/alina/wong)은 Sketchfab 에서 사람이 받아온 에셋이다** — API 호출
코드는 없다. `docs/STATE.md:82` 에 라이선스 미확인이 미해결로 남아 있다.

**런타임 CDN 의존이 하나 있다.** 캐릭터 GLB 가 Draco 압축본이라 `gstatic.com` 의 디코더를
받아온다. 이 CDN 이 막히면 `mount()` 가 `null` 을 돌려주고 게임은 2D 사진 폴백으로 계속
돌지만, **오프라인·차단망 시연에서는 3D 가 뜨지 않는다.** 디코더를 self-host 하지 않은 것은
남은 부채다.

비활성화돼도 초록불을 낸다.

### 6.2 게이트가 걸린 지점

| 지점 | 무엇을 막나 | 실패하면 |
|---|---|---|
| **빌드 타임** — `gen-pool.mjs` | 런타임 사건 생성 재시도 | 첫 시도 통과 시드가 200개 미만이면 `throw` |
| **커밋** — `.githooks/pre-commit` | 테스트·타입·빌드 깨진 커밋 | `exit 1`, 커밋 중단 |
| **CI** — `ci.yml` | 로컬 훅 우회분 | 워크플로 실패 |
| **런타임** — `verifyReply()` | 사건에 없는 사실을 말하는 응답 | 1회 재요청 → 폴백 |
| **라이브** — `npm run audit:persona` | 페르소나 8종이 서로 같아지는 것 | 버릇 검출 <7/8 또는 최대 유사도 ≥0.55 면 `exit 1` |
| **자동 플레이테스트** — `npm run review` | "재미없다"류의 자연어 결함 | 연속 3회 무지적이 아니면 `exit 1` |
| **사람 눈** — 브라우저 실측 | 위 어느 것도 못 잡는 층 | §4.4 |

시드 풀은 이 게이트 중 성격이 다르다. `generateValidCase` 는 원래 게임 시작 시점에 돌면서
검증 실패 시 최대 40회 재생성했다. 시드 1~3000 을 스캔한 결과 **첫 시도 통과율 100.0%
(3000/3000)** 였는데 — 그건 사실이지 보장이 아니었다. 그래서 통과 시드를 스캔 범위 전체에
고르게(7 간격) 400개 솎아 `src/data/pool.json` 에 굽고, `tests/pool.test.ts` 가 매번 400개
전부를 `maxAttempts=1` 로 재검증한다 (실측 278ms). **풀 경로의 런타임 재시도는 0회다.**
`?seed=` 로 들어온 임의 시드는 여전히 재시도 경로를 탄다 — 의도된 예외다.

굽는 값은 **시드 그 자체**다. 사건 객체를 구우면 서버가 같은 시드로 재생성하는 계약이 깨지고,
생성기를 고칠 때마다 구운 데이터가 조용히 낡는다.

### 6.3 페르소나가 실제로 갈라지는지

페르소나 8종은 문장 성향·버릇·회피어·**압박 반응** 4요소 카드로 정의된다
(`src/data/personas.ts`). 설계 의도가 5~8행에 적혀 있다 — "`pressureResponse` 가 진짜
차별점이다. 나머지 셋은 장식이고 이것만이 플레이어의 전략을 바꾼다." 접근법이 겹치는 조합은
같은 판에 배정되지 않는다 (`PERSONA_CONFLICTS = [['timid','guilty']]`).

두 층에서 검사한다. 결정론 층은 `tests/llm.test.ts:67-84` — 8종의 4요소가 전부 채워져 있고
`pressureResponse` 8개가 서로 다름(Set 크기 == 8)을 고정한다. 라이브 층은
`npm run audit:persona` — 배포된 엔드포인트에 같은 시드·같은 질문·같은 압박으로 8회 호출해,
각 페르소나의 버릇 흔적이 검출되는지와 쌍별 문자 2-gram 자카드 유사도를 잰다. 합격선이
코드에 박혀 있다 (`persona-audit.mjs:80-82`): **버릇 검출 ≥7/8 이고 최대 유사도 <0.55.**

기록된 실행 결과는 **버릇 검출 8/8, 최대 유사도 21.4% (timid ↔ guilty)** 이고, 가장 비슷하게
나온 쌍이 `PERSONA_CONFLICTS` 에 미리 박아둔 동시출현 금지 조합과 일치했다 — 설계 제약이
실측으로 확인된 셈이다. 이 감사는 실제 LLM 을 호출하므로 느리고 비용이 들고 비결정론적이라
CI 에 넣지 않았다 (`persona-audit.mjs:7-8`). 위 8/8·21.4% 는 저장소에 기록된 1회 실행 결과이며,
이 문서를 쓰면서 재실행하지는 않았다.

### 6.4 밸런스 회귀

봇 3종이 시드 100개를 돌려 승률로 판정한다. 이번 실행 실측:

| 봇 | 승률 | 평균 소모 | 판정 근거 |
|---|---|---|---|
| 완벽 봇 | **100%** | 4.3회 | 사건이 실제로 풀린다는 증명 |
| 상식 봇 | **64%** | 9.0회 | 목표 구간 60~75% 안 |
| 무작위 봇 | **46%** | 9.0회 | 찍어서 되는 게임이 아니다 |

상식 봇 승률은 한때 44%까지 떨어져 테스트를 todo 로 잠갔던 항목이다. 예산을 9회로 올려
구간 안으로 들어온 뒤 잠금을 풀어 회귀를 감시한다. (ADR 009 의 스윕 표는 9회에서 60%였고
현재 64%인 것은 이후 변경들의 누적 결과다 — 표의 숫자를 그대로 옮기지 않고 매 실행 실측을 본다.)

시간은 행동 구성을 벽시계로 환산한다. 실측 출력:

```
평균 행동 구성: 심문 3.0 · 제시 2.4 · 조회 3.6
숙련  평균 1분 16초 · p95 1분 20초 · 최악 1분 27초   (상한 5분 00초)
초회  평균 2분 46초 · p95 2분 50초 · 최악 2분 57초   (상한 6분 30초)
 └ 민감도: 심문당 작문·타이핑 30초 가정 → 숙련 평균 2분 46초 · 초회 최악 5분 27초
```

이 환산 모델은 **사람이 질문을 작문·타이핑하는 시간을 세지 않는다.** 봇은 대상만 고르면
되지만 사람은 한글 IME 로 한 문장을 친다. 숫자를 숨기지 않으려고 민감도(심문당 10/20/30초)를
함께 찍는다. 그리고 환산의 전제 자체를 먼저 잠근다 — 로그 줄 수가 실제 소모 조사 수와
일치하는지 확인하는 테스트가 앞에 있고, 이게 깨지면 시간 숫자는 전부 거짓말이 된다.

## 요약

이 프로젝트에서 AI 는 두 번 쓰였다. 게임 안에서 다섯 명의 용의자를 연기했고, 게임 밖에서
코드와 에셋과 리뷰를 만들었다. 두 자리 모두에서 같은 경계를 그었다 — **만들게 하되,
들어갈지는 결정론적인 것이 정한다.**

런타임에서는 순수 함수 하나(`game.ts`)가 자원·판정·점수를 전부 쥐고 있어서, LLM 이 돌려주는
동요 수치는 검증기를 통과하고도 소비되지 않는다. 파이프라인에서는 `.githooks/pre-commit` 이
테스트 136건 + 타입체크 2종 + 빌드를 통과하지 못한 코드를 커밋조차 못 하게 막는다.

그 경계를 지키게 만든 것은 설계가 아니라 실패였다. 6회라는 예산이 누설 위에 서 있었다는 걸
안 것도, 한 번의 0건이 수렴이 아니라는 걸 안 것도, 앉혔다던 8명이 전부 서 있었다는 걸 안 것도
전부 숫자를 다시 재고 나서였다. §4 가 이 문서에서 가장 긴 이유다.
