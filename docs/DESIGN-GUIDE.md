# 디자인 가이드 — FIVE ALIBIS

> 팀 명세 **3-2-(5)-(1) 3단계** 산출물. 색 값의 정본은 [`src/styles/tokens.css`](../src/styles/tokens.css) 이고,
> 이 문서는 **왜 그 값인지와 어디에 쓰는지**를 정한다. 값이 필요하면 코드를 보라 — 여기에 색을 복사해 두지 않는다.
>
> 이 가이드가 없던 동안 화면마다 팔레트가 갈라졌다. 팀 진단: *"칠판과 좌측 사이드바, 프로파일링 문서가
> 서로 다른 게임의 UI처럼 보인다."* 맞는 진단이었고, 원인은 취향이 아니라 **기준의 부재**였다.

---

## 1. 한 줄

**반실사 카툰 누아르** — 현실적인 공간감과 조명 위에, 연필선·종이 질감·거친 채색을 얹는다.

기준점은 **도입부 카툰**이다. 다른 어떤 화면도 기준이 아니다. 새 화면을 만들 때 물어야 할 질문은
"예쁜가" 가 아니라 **"도입부 그 종이와 같은 세계의 물건인가"** 다.

두 극단을 다 버린다:

| 버린 쪽 | 왜 |
|---|---|
| 완전한 카툰 (플랫·굵은 윤곽·채도 높은 색) | 분위기가 가벼워진다. 추리게임의 긴장이 안 선다 |
| 완전한 실사 (사진·물리 기반 렌더) | 도입부 삽화가 가진 거리감·손맛과 어긋난다 |

**형태는 현실 비율, 표면은 삽화.** 인체 비율·실내 공간감·소품 크기는 현실적으로 두고,
윤곽선과 표면 렌더링만 삽화적으로 처리한다 (3-2-(5)-(4) 2단계).

---

## 2. 다섯 색 — 그 밖의 색은 쓰지 않는다

| 재질 | 토큰 | 어디에 |
|---|---|---|
| **먹색** | `--fa-ink-*` | 화면 바탕 · 판 · 괘선. 검정 대신 갈색기 도는 어둠 |
| **어두운 갈색** | `--fa-wood-*` | 나무 프레임 · 가죽 장정 · 책상 |
| **바랜 종이** | `--fa-paper*` | 파일철 · 수첩 · 프로파일링 문서 · 조서 |
| **탁한 녹색** | `--fa-slate*`, `--fa-chalk*` | 칠판 면과 분필. 교실 초록이 아니라 조명 아래 슬레이트 |
| **붉은 포인트** | `--fa-red-chalk`, `--fa-red-seal` | 범행 시각(붉은 분필) · 모순(인장). **강조는 화면당 한 종류** |

한 점만 더 있다: **놋쇠**(`--fa-brass`) — 문패·클립·책등 띠처럼 금속이어야 하는 자리에만.

### 색만으로 상태를 말하지 않는다

붉은색을 쓸 때는 **형태·활자·위치 중 최소 하나**를 함께 준다.
칠판의 어긋난 칸이 그 예다 — 붉은 ✕ 획(형태) + `어긋남` 표(활자)가 색과 함께 간다.
색약·저대비 화면·흑백 캡처에서도 정보가 살아 있어야 한다.

> 옛 비주얼 바이블(`ART_DIRECTION_STATUS: LOCKED`)은 "빨강 = 범인/거짓말 금지" 를 못 박았고
> 3-2-(5) 가 그것을 덮어썼다(**최신 지시가 이긴다**). 하지만 위 원칙은 그대로 유효하다.

---

## 3. 한 개의 광원

이 세계에는 **갓등 하나**가 있다. 빛은 위에서 약간 왼쪽으로 떨어지고, 나머지는 어둠이다.

- 그래서 `--fa-lamp` 는 화면 상단 왼쪽 기준의 원뿔로 깐다. 화면마다 빛의 방향이 달라지면
  오브젝트들이 같은 방 안의 물건으로 안 읽힌다.
- 그림자는 검게 막지 않는다. 완전히 검은 그늘은 형태 정보를 지운다 —
  차가운 필(`--fa-lamp` 의 반대색)로 그늘에 정보를 남긴다. (취조실 3D 가 같은 규칙을 쓴다.)
- **어둡게 만드는 일은 조명이 한다.** 베이스 색을 눌러서 어둡게 하면 재질 구분이 함께 사라진다
  (`stage3d.ts` 에서 실제로 그렇게 실패한 적이 있다).

---

## 4. 질감 — 균일한 면은 재질이 아니다

균일한 초록은 칠판이 아니라 초록 사각형이고, 균일한 베이지는 종이가 아니라 베이지 사각형이다.
네 층으로 재질을 만든다:

1. **얼룩** — vignette · 지우개 자국 · 물때. 중심이 밝고 네 귀퉁이가 어둡다
2. **결** — `--fa-grain` (feTurbulence data URI). `multiply` 나 `soft-light` 로 얹는다
3. **손** — 획이 자로 잰 듯 놓이지 않는다. 미세한 기울기·압력 변화.
   **`Math.random()` 금지** (불변식 5) — 좌표로 결정되는 고정 표에서 뽑는다
4. **끝의 흐림** — 분필 획 끝, 잉크 번짐, 종이 가장자리의 그늘

외부 이미지 에셋을 늘리지 않는다. 위 네 층은 전부 CSS 와 data URI 로 선다 (배포 무게 0).

---

## 5. 오브젝트 — 화면이 아니라 사건실이다

메인 페이지는 메뉴가 아니라 **어두운 조사실 안의 알리바이 보드**다 (3-2-(5)-(5)).

```
[좌] 파일철 · 용의자 목록      [중앙] 조명이 떨어지는 칠판      [우] 가장자리에 꽂힌 수첩
```

- 인터랙션 오브젝트는 전부 **아날로그 물건**이다 — 종이 · 파일철 · 칠판 · 사진 · 인장.
  버튼처럼 생긴 버튼, 카드처럼 생긴 카드, 탭처럼 생긴 탭을 쓰지 않는다
- 열고 닫는 동작은 **물성에 맞게**: 수첩은 옆에서 펼쳐지고, 파일철은 덮개가 열린다 (3-2-(5)-(3) 2단계)
- **장식을 줄인다.** 아이콘·테두리·배지를 늘리는 대신 종이·잉크·분필의 재질감으로 분위기를 만든다
  (3-2-(5)-(3) 3단계). 아이콘이 필요하면 그것이 실제 물건인지 먼저 묻는다
- 배경은 비우지 않되 **튀지 않는다.** 미세한 벽면 질감·그림자·조명 번짐까지. UI 보다 앞에 나오면 실패다

### 화면 밀도 상한

핵심 텍스트 블록 **2~3개**. 이걸 넘으면 무엇을 읽어야 할지 화면이 말해 주지 못한다.
취조실이 이 상한을 어겼다가 3-3-(1) 지적을 받았다 — 정보를 더 넣는 대신 **다른 뎁스로 옮긴다.**

---

## 6. 화면별 역할 — 정보를 두 곳에서 말하지 않는다

| 화면 | 역할 | 여기에 **없어야** 하는 것 |
|---|---|---|
| 칠판 | 알리바이 대조. 한 사람의 시간선을 왼→오로 읽는다 | 인물 배경·성향 |
| 파일철 / 프로파일링 문서 | **인물을 이해하는 공간** — 배경·관계·성향 | 대화 |
| 수첩 (드로어) | 내가 지출한 내역 · 손에 쥔 기록 | 새 정보 (보상 화면이 되면 안 된다) |
| 취조실 | **실제로 대화하는 공간** | 인물 배경·성향 (3-3-(2)) |

같은 정보를 두 화면에 두면 둘 다 약해진다. 3-3-(2) 가 정확히 그 지적이다.

## 7. 활자

| 쓰임 | 서체 | 왜 |
|---|---|---|
| 조서·머리말·인물 이름 | `--fa-serif` (명조) | 손으로 적은 문서의 활자 |
| 시각·기록번호·상태 라벨 | `--fa-mono` | 데이터는 고정폭으로 읽는다. 자리가 흔들리지 않는다 |
| 본문·안내 | `--fa-sans` | 긴 한국어 문장의 가독성 |

한국어는 `word-break: keep-all` 로 어절을 지킨다. 괘선이 있는 면에서는 **행간을 괘선 간격의
정수배**로 못 박는다 — 하나라도 어긋나면 그 아래 모든 줄이 줄에서 밀려 나가고, 종이는
"줄 위에 쓴 글" 이 아니라 "줄무늬 배경에 얹은 글" 이 된다.

## 8. 대비 — 이건 취향이 아니다

**본문 4.5:1 · 큰 글씨 3:1** (WCAG AA). 값을 눈으로 정하지 않고 **잰다.**

실제로 이 규칙이 없어서 드로어 안의 글이 **1.12:1** 로 배포됐다 — 밝은 종이 위에 밝은 잉크였고,
아무도 읽을 수 없었다. 원인은 부품(밝은 종이)과 내용(어두운 판 전제)이 서로 다른 팔레트를
가정한 것이다. **부품 경계를 넘을 때 색이 상속되는지 반드시 확인한다.**

토큰의 기본 짝은 이미 통과된 값이다 (실측):

| 짝 | 대비 |
|---|---|
| `--fa-paper-ink` on `--fa-paper` | 12.8:1 |
| `--fa-paper-ink-soft` on `--fa-paper` | 5.65:1 |
| `--fa-chalk` on `--fa-slate` | 12.3:1 |
| `--fa-red-chalk` on `--fa-slate` | 4.5:1 |

## 9. 부품이 지켜야 하는 것 (실패에서 나온 목록)

- **부품은 자기 CSS 를 자기가 `import` 한다.** 주석으로 언급하고 import 를 빠뜨려
  화면을 덮거나 문서 흐름에 낀 사고가 두 번 있었다
- **CSS 는 자기 CSS 맨 위에서 `@import './tokens.css'`** 하고, 값은 **폴백을 안고** 쓴다
  (`var(--fa-paper, #e6dfcd)`). 그러면 `probe-*.html` 단독 하네스에서도 같은 색으로 선다
- **스코프가 래퍼 하나만 가정하지 않는다.** `.nb.interview` 로만 적힌 규칙 98줄이
  제2막(`.act2.interview`)에서 통째로 죽어 있었다 — 700px 창에서 대화 로그 높이가 0이었다
- `display: contents` 를 쓴 요소는 `getBoundingClientRect()` 가 전부 0을 준다.
  측정과 `.parent > *` 규칙은 실제 그리드 항목에 걸어라
- `all: unset` 은 `position` 을 `static` 으로 되돌린다

## 10. 톤을 맞추는 순서 (3-2-(5)-(4) 3단계)

플레이어가 **가장 먼저 보고 가장 오래 보는** 화면부터.

```
도입부 카툰(기준) → 칠판 타임라인 → 취조실 → 프로파일링 문서 / 수사일지 → 결과 화면
```

한 번에 전부 바꾸지 않는다. 각 단계는 배포 가능한 상태로 끝난다.
