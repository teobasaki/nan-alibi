## 2. 충돌 목록 — 사용자 결정 필요

### C-1. 칠판 자동 소거와 Core Loop "시스템 자동 후보 제외 제거" 충돌

- **문서 지시:** Core Loop Migration §4 "시스템이 자동으로 후보를 제외하는 행위를 제거한다"
- **현행 코드:** `chalkboard.ts:110` → `candidatesFrom()`(solver.ts) 결과로 `cleared: true` → 이름에 분필 줄 긋기. GC-001에서도 decisive 기록 획득 시 자동 소거가 표시된다.
- **결정 선택지:**
  - (a) GC-001일 때 `cleared` 를 항상 `false` 로 넘겨 줄을 없앤다 (V0.2 정신 존중)
  - (b) 칠판 소거는 "판정"이 아닌 "시각 힌트"로 간주하고 유지한다 (플레이 보조)
  - (c) `candidatesFrom`을 GC-001 전용으로 분기해 Proof 기반 소거만 반영한다

### C-2. 근거 제출 개수 — 명세 "2~4개" vs 구현 `max:6`

- **명세 §31:** "근거 2~4개 선택"
- **코드:** `gc001-proof.ts:127` → `GC001_CLUE_PICK = { min:2, recommended:4, max:6 }`
- **이유:** 두 축(범인+방식)을 동시 PROVEN 하려면 `given`을 빼도 실측 최소 6장 필요한 조합 존재
- **결정 선택지:**
  - (a) 명세를 개정해 "2~6개"로 올린다 (현 코드 유지)
  - (b) SupportRule을 줄여 4개로 증명 가능하게 데이터를 재설계한다

### C-3. presentUnlocks 잔존 — "선택적 지름길" vs 금지 2 경계

- **ADR 031:** "진행의 필수 경로에서 빠진다. 선택적 지름길이 된다"
- **명세 금지 2:** "특정 Evidence를 특정 NPC에게 제시 → 다음 핵심 단계" 금지
- **현행:** `gc001.ts`에 4개 presentUnlocks 데이터 존치, `game.ts:presentEvidence()` 활성
- **결정 선택지:**
  - (a) GC-001 UI에서 증거 제시 버튼을 숨겨 경로를 차단한다
  - (b) 힌트로 유지하되, 해금이 Proof에 영향 없음을 보장한다 (현행)

## 부록: 문서 간 방향 정합 확인

네 에이전트 보고서 모두 "문서 5개 사이에 **충돌하는 지시는 없다**"고 결론 냈다.
취조실 문서(3-3)의 모든 제언은 V0.2 명세의 부분집합이거나 같은 방향이며,
V0.2가 이를 구현 기준으로 격상시켰다. 3.2.16의 연출 요구는 3-2-(5) 디자인 가이드와
동일한 팔레트·물성 위에서만 발동하므로 상호 보완 관계다.

유일한 긴장 지점은 §2에 나열한 3건이며, 이것은 "문서 간 충돌"이 아니라
"명세 문자 vs 구현 실측값"의 차이다 — 사용자가 정한다.
