# FIVE ALIBIS — 프롬프트 운용 문서

> NAN 2026 제출물 ④ 부속 · 작성 2026-08-10
> 이 문서는 "무엇을 시켰나"가 아니라 **"어떻게 시켜야 낭비가 없는가"**를 적는다.
> 모든 예시는 이 프로젝트에서 실제로 쓴 것이고, 실패한 것도 함께 적는다.

## 0. 한 줄

> **프롬프트는 부탁이 아니라 계약이다.**
> 기대 행동 · 검증 방법 · 실패 시 행동 · 중단 조건을 적지 않은 지시는 지시가 아니라 소원이다.

## 1. 다섯 원칙

### 원칙 1 — BDD: 기대 행동을 먼저 문장으로 못박는다

"이렇게 만들어 줘"가 아니라 **"이런 상황에서 이렇게 되면 통과"**를 먼저 쓴다.
`Given / When / Then`은 사람에게도 모델에게도 같은 문장이고, **그대로 테스트가 된다.**

```text
Given  현장에 같은 종류의 기록이 4건 있고
When   증거를 배치하면
Then   화면에 같은 3D 모델이 두 번 나타나지 않는다
       (제 종류 풀이 동나면 다른 종류의 남은 실모델을 빌리고, 카탈로그를 다 쓴 뒤에야 깃발)
```

이 세 줄이 곧 `tests/scene.test.ts`의 한 케이스가 됐다. **문장을 못 쓰면 코드도 못 쓴다** —
못 쓰겠으면 그건 아직 기획이 안 끝난 것이고, 원칙 4의 게이트로 간다.

> 실제 효과: 옛 테스트는 "깃발 3개가 나오면 통과"였다. 그래서 사용자가 다섯 번 신고한
> 증상이 **테스트를 통과하며** 살아 있었다. Then 문장이 틀리면 초록도 거짓말을 한다.

### 원칙 2 — 가드레일: 금지어가 아니라 **검증 가능한 계약**으로

"거짓말하지 마세요"는 가드레일이 아니다. 지켰는지 기계가 판정할 수 없기 때문이다.
우리 가드레일은 전부 **판정 가능한 형태**로 쓴다.

| 약한 가드레일 (쓰지 않음) | 우리가 쓰는 형태 | 기계 판정 |
|---|---|---|
| "사건에 없는 정보를 말하지 마" | 말할 수 있는 사실 id 목록을 프롬프트에 넣고, 응답의 `revealedFactIds`가 그 밖이면 폐기 | `unknown-fact` |
| "짧게 말해" | 120자 상한 | `too-long` |
| "시간을 지어내지 마" | 사건의 시각 라벨 집합 밖이면 폐기 | `phantom-time` |
| "애매하게 말하지 마" | "22:00부터 22:30까지" 같은 **구간 표현** 금지 | `time-range` |

**핵심은 이중화다.** 프롬프트로 막고(규칙 9), 새면 검증기가 잡는다(`time-range`).
프롬프트만 믿으면 언젠가 새고, 검증기만 두면 재요청이 잦아 느려진다.

그리고 **모르게 하는 것이 가장 센 가드레일이다.**
범인에게 자기가 범인이라는 사실을 주지 않으면, 그 정보가 새어나갈 경로 자체가 없다.
"알려주면서 말하지 말라"고 하는 것은 유출 설계다.

### 원칙 3 — 루프: **수렴 조건을 먼저** 정한다

에이전트를 루프로 돌릴 때 제일 먼저 쓰는 것은 시작 조건이 아니라 **끝 조건**이다.

```text
[수렴 조건] 연속 3회 무지적일 때만 수렴으로 친다.
[근거] 1회 0건을 수렴이라 선언한 직후, 같은 빌드에서 5건이 나왔다.
       한 번의 침묵은 수렴이 아니라 표본 부족이다.
[상한] 최대 8라운드. 넘으면 수렴 실패로 보고하고 사람에게 넘긴다.
```

루프에는 세 가지가 반드시 붙는다:

1. **수렴 조건** (연속 N회 무지적 / 목표 수치 도달)
2. **하드 상한** (라운드 수 또는 토큰 예산) — 없으면 랄프 루프는 돈 태우는 기계가 된다
3. **탈출 시 보고 형식** — 무엇을 시도했고 왜 못 끝냈는지

> **랄프 루프(자기 출력을 다시 먹여 끝까지 도는 루프)를 쓰는 조건**:
> 정답이 **기계로 판정 가능**할 때만 쓴다 (테스트 초록·수치 도달·린트 0).
> 판정이 사람 취향이면 루프는 수렴하지 않고 진동한다 — 그때는 1회 실행 후 사람에게 올린다.

### 원칙 4 — 비용: 모델 라우팅은 **작업의 성격**으로 정한다

같은 모델로 전부 돌리는 것은 비싸거나 멍청하다. 우리는 이렇게 갈랐다.

| 작업 | 라우팅 | 왜 |
|---|---|---|
| 런타임 대사 생성 (판당 40~50회) | **`gpt-4o`, `effort=none`** | 추론이 필요 없는 연기. 실측으로 5.4-mini보다 빨랐다(2066ms vs 2624ms) |
| 대량 기계 작업 (에셋 굽기·리타게팅·썸네일) | **저비용 모델 + 스크립트** | 판단이 아니라 반복. 사람 판단은 검수 한 번에만 |
| 코드 수리 · 버그 계측 | **중상위 모델 + 계측 강제** | 원인 추정이 필요하지만 정답이 수치로 판정된다 |
| **새 개념 · 새 기획의 적대적 검증** | **codex sol 5.6 extra high, 딱 1회** | 가장 비싼 호출은 **가장 늦게, 한 번만.** 여러 번 돌릴 거면 애초에 기획이 안 된 것 |
| 정해지지 않은 기획 | **모델 호출 금지 → Discord 선보고** | 아래 §2 |

**비용 원칙 한 줄:** *싼 모델로 많이, 비싼 모델로 한 번.*
그리고 **비싼 호출 앞에는 반드시 게이트를 둔다** — 게이트 없이 비싼 모델을 돌리는 건
"뭐라도 나오겠지"이고, 그건 프롬프트 엔지니어링이 아니라 도박이다.

---

### 원칙 5 — 실패: **조용히 실패하지 않는다**

세 층에서 같은 규칙을 쓴다.

| 층 | 실패했을 때 |
|---|---|
| 런타임 LLM | 1회 재요청 → 폴백 대사 → **소모한 조사 횟수 환불** |
| 에이전트 작업 | 시도한 것·수치·왜 못 했는지를 **보고**. "고쳤습니다"만 쓰는 것은 금지 |
| 사람 판단 필요 | 루프 중단 → **Discord 선보고** |

> 이 프로젝트에서 가장 비쌌던 실패는 **"고쳤다고 보고했는데 안 고쳐진 것"** 이었다.
> 커밋만 보고 배포를 확인하지 않아 같은 버그를 세 번 보고받았다.
> 그래서 규칙이 생겼다 — **배포는 번들 해시를 대조한 뒤에만 완료라고 말한다.**

## 2. 게이트 — 루프를 돌리면 **안 되는** 순간

**Pre-mortem 질문:** *"이 작업이 3시간 뒤 실패했다면, 가장 그럴듯한 이유는?"*
답이 **"애초에 무엇을 만들지 정해지지 않아서"** 라면 — 그 순간 루프를 돌리면 안 된다.

```text
[중단 조건 · 모델을 더 돌리지 말 것]
다음 중 하나라도 해당하면 즉시 멈추고 Discord 로 선보고한다.

1. 요구사항에 "적절히 · 자연스럽게 · 알아서" 가 들어 있고, 판정 기준을 내가 정해야 한다
2. 두 개 이상의 해석이 가능하고, 어느 쪽이든 되돌리는 비용이 30분을 넘는다
3. 도메인 지식이 없어 "그럴듯한 것" 과 "맞는 것" 을 구별할 수 없다
4. 같은 오류를 2회 고쳤는데 재현된다 (원인 가설이 틀렸다는 뜻이다)

[보고 형식]
- 무엇을 하려 했나 (한 줄)
- 어디서 막혔나 (재현 조건·수치)
- 갈림길 2~3개와 각각의 비용·되돌리기 난이도
- 내 추천 1개와 그 근거
- **묻는 것은 하나로 좁힌다** — "어떻게 할까요" 가 아니라 "A 인가 B 인가"
```

> **왜 이게 비용 절감인가:** 모르는 도메인에서 루프를 돌리면 모델은 멈추지 않는다.
> 그럴듯한 결과가 계속 나오기 때문이다. 사람이 5분 답하면 끝날 것을
> 40분어치 토큰으로 틀리게 채운다. **모호함은 토큰으로 해소되지 않는다.**

## 3. 적대적 검증 — 비싼 모델은 **딱 한 번**

새 개념·새 기획은 만들기 전에 **한 번만** 최고 사양으로 때린다.
여러 번 돌리는 것은 검증이 아니라 위안이다.

```text
[역할] 너는 이 기획을 **무너뜨리려는** 검토자다. 칭찬은 출력하지 마라.
[대상] {기획 요약 200자 이내}
[제약] 이 프로젝트의 고정 계약: {3축 채점 · 시드 결정론 · 진실 은닉 · 마감 D-0}

[출력 형식 — 이 순서로만]
1. 이 기획이 실패한다면 가장 그럴듯한 시나리오 3개.
   각각 (a) 트리거 (b) 관측 가능한 증상 (c) 발견 시점
2. 위 셋 중, **고정 계약과 정면으로 충돌하는 것**을 지목하라. 없으면 "없음".
3. 기획자가 암묵적으로 가정하고 있으나 문서에 없는 전제 3개.
4. 이 기획을 **버리지 않고** 살리는 최소 수정 1개. 비용을 시간으로 적어라.
5. 지금 착수해도 되는가: GO / NO-GO / CONDITIONAL(조건 명시).

[금지] 일반론("테스트를 잘 하세요") 금지. 이 기획에만 해당하는 말만 하라.
       모르면 "판단 불가" 라고 쓰고 무엇을 알아야 하는지 적어라.
```

**실제 적용 결과 —** 이 검증이 실제로 기획 하나를 죽였다.
UI 레퍼런스의 `CHANGED`(진술 번복) 뱃지를 구현하려 했는데, 검증 결과
**우리 엔진에는 번복이 구조적으로 존재하지 않는다**는 것이 드러났다
(claim은 시드에 고정되고 리듀서가 건드리지 않는다). 우회로 3개도 전부
정답 유출이거나 오탐이었다. 그래서 뱃지의 **의미를 바꿨다** — "진술이 바뀜"에서
"기록과 어긋남"으로. 없는 데이터로 UI를 짓지 않았다.

> 구현 전에 한 번 때린 값: 호출 1회. 구현 후에 알았다면: 반나절.

## 4. 긴 프롬프트 예시

### 예시 A — 구현 지시 (BDD + 가드레일 + 소유권 + 검증)

실제로 서브에이전트에게 보낸 형식이다. **파일 소유권**이 들어가는 이유는
여러 에이전트가 동시에 도는 환경에서 같은 파일을 고치면 서로의 작업을 덮기 때문이다.

```text
[맥락] FIVE ALIBIS — 한국어 브라우저 추리 게임. 마감 D-0. 저장소 {경로}.
       dev 서버는 :5181 에 이미 떠 있다.

[목표 · BDD]
Given  플레이어가 30초 현장에서 증거를 0개 수집하고 시간이 끝났을 때
When   수사 정리 시트가 열리면
Then   "다시 들어간다" 또는 "기록철로 대체" 중 하나를 반드시 제공한다
       (지금은 조사 5/5 로 처리되고 모든 조회가 비활성이라 추리가 불가능하다)

[담당 파일 — 이것만 수정한다]
  src/main.ts · src/ui/sceneRules.ts
[금지 — 다른 에이전트가 동시에 편집 중이다]
  src/ui/crimescene3d.ts · explore3d.ts · stage3d.ts
  필요하면 수정하지 말고 **보고**하라.

[가드레일]
- 엔진(src/engine/)의 판정 규칙을 바꾸지 마라. UI 계층에서 해결하라.
- 새 텍스트는 한국어. 유혈·수단·신체 묘사 금지(정본 §4).
- `git add -A` 금지. 자기 파일만 스테이징.
- 커밋 제목 72자 이내, `[FIX] 한국어` 형식. 상세는 본문으로.

[검증 — 이걸 통과해야 완료다]
1. `npx vitest run` 308건 초록 유지 (새 케이스 추가는 환영)
2. `npm run build` 초록
3. **브라우저로 실제 플레이**해 0개 수집 경로를 재현하고, 복구가 뜨는 것을 확인
4. 콘솔 에러 0

[실패 시]
- 3번을 재현하지 못하면 "재현 실패" 로 보고하라. 추측으로 고치지 마라.
- 담당 밖 파일이 필요하면 그 사실과 이유를 보고하고 멈춰라.

[보고 형식] 커밋 해시 · 테스트/빌드 결과 · 재현한 경로 · 남은 문제(정직하게)
```

### 예시 B — 버그 수리 (계측 강제 · 추측 금지)

**같은 버그를 세 번 보고받은 뒤** 만든 형식이다. 핵심은 한 줄 —
*"고치기 전 수치를 먼저 기록하라."*

```text
[신고 원문] "3인칭으로 이동할 때 버벅이고 순간이동하고, 캐릭터는 바닥에 묻혀있다"
            — 사용자, 3회차 신고

[절대 규칙]
이전 두 라운드에서 "고쳤다" 고 보고했으나 실제로는 안 고쳐졌다.
이번엔 **재현 → 계측 → 수리 → 같은 계측 재확인** 을 반드시 거친다.
**계측값이 없으면 보고하지 마라.**

[증상을 수치로 정의하라 — 형용사 금지]
1. 버벅임 = rAF 프레임 간격의 p50/p95/최대, 16.7ms 초과 프레임 비율
2. 순간이동 = |Δpos| / dt 가 설정 이동속도를 넘는 프레임의 개수 (1건이라도 있으면 버그)
3. 바닥 묻힘 = 캐릭터 루트 world y 와 실제 바닥 y 의 차
   (먼저 모델 원점이 발밑인지 골반인지 바운딩박스로 확인할 것)

[가설 — 확인하되 여기 갇히지 마라]
- dt 상한(clamp) 부재로 큰 프레임 간격이 한 번에 적분됨
- 지면 클램프가 1인칭에만 있고 3인칭에 없음
- 애니메이션 클립에 루트 모션이 구워져 위치에 누적됨
- 충돌 격자가 로우폴리 벽에서 성기게 구워짐

[절차]
1. 브라우저로 해당 화면까지 실제 진입
2. 계측 스크립트 주입 → **고치기 전 값 기록**
3. 원인 특정 후 수리
4. 같은 계측 재실행 → **전/후 표로 보고**
5. 스크린샷으로 육안 확인

[보고 필수 항목] 전/후 수치 표 · 원인 한 줄 · 커밋 해시 · 재현 못 한 증상
```

> **실제 결과:** 세 증상이 서로 다른 원인이었다.
> 걷는 면이 y=0.538인데 배치가 y=0을 전제(묻힘 0.538m → 0.000m),
> 한 프레임이 0.25초를 적분(도약 0.42m → 0.17m),
> 그림자 패스가 삼각형의 49%(44만 → 33만). 가설 하나만 믿었으면 셋 중 하나만 고쳤을 것이다.

### 예시 C — 조사 지시 (읽기 전용 · 구조화 출력)

병렬 조사에 쓴 형식. **판정 어휘를 미리 고정**해 결과를 기계로 합칠 수 있게 한다.

```text
[역할] 읽기 전용 조사자. **파일을 수정하지 마라. git 상태를 바꾸지 마라.**
       다른 에이전트가 지금 이 저장소를 편집 중이다.

[담당] {영역 1개}
[질문] {3~5개, 각각 예/아니오 또는 수치로 답할 수 있는 형태}

[판정 어휘 — 이 넷 중 하나만 쓴다]
  이미있음 / 부분 / 없음 / 충돌
  · "충돌" = 그대로 하면 우리 고정 계약(3축 채점·시드 결정론·진실 은닉)이 깨진다는 뜻이다.
    "없음" 과 반드시 구별하라.

[비용 판정] 소(1시간 내) / 중(반나절) / 대(하루+) — 마감 D-0 기준으로 냉정하게

[증거 규칙] 추측 금지. 파일을 열어 확인하고 `파일:줄번호` 를 근거로 붙여라.

[질문 목록에 넣을 것] 코드를 읽어도 알 수 없는, **사람만 답할 수 있는 것**만.
```

### 예시 D — 마스터 오케스트레이션 프롬프트 (한 번에 다 보이는 것)

위 전부를 하나로 묶은 형태다. 새 작업을 에이전트에게 넘길 때 이 틀을 채운다.

```text
════════════════════════════════════════════════════════════
 작업 계약서 — {작업명}
════════════════════════════════════════════════════════════

■ 맥락
  프로젝트 {이름} · 마감 {D-n} · 저장소 {경로} · 실행 {명령}
  지금 동시에 도는 다른 작업: {목록 또는 "없음"}

■ 기대 행동 (BDD — 통과 기준이자 테스트가 될 문장)
  Given {상태}
  When  {행동}
  Then  {관측 가능한 결과. 형용사 금지, 수치나 참/거짓으로}
  (여러 개면 번호를 매긴다. 못 쓰겠으면 착수하지 말고 ■게이트로 간다)

■ 소유권
  담당 파일: {목록}          ← 이것만 수정한다
  금지 파일: {목록}          ← 필요하면 수정하지 말고 보고
  공용 자원: {DB·배포·시크릿 등} ← 건드리기 전 반드시 확인

■ 가드레일 (검증 가능한 형태로만)
  - {계약 1: 깨지면 기계가 알아채는 형태}
  - {계약 2}
  - 커밋: 제목 {n}자 이내, `{형식}`. `git add -A` 금지
  - 비밀값·키를 출력·커밋하지 마라

■ 모델·비용
  이 작업 등급: {기계반복 | 코드수리 | 신개념}
  → 라우팅: {저비용 배치 | 중상위+계측 | 최고사양 1회}
  토큰 상한: {값} · 초과 시 중단하고 보고

■ 루프
  수렴 조건: {연속 N회 무지적 | 수치 도달 | 테스트 초록}
  하드 상한: {라운드 수}
  진동 감지: 같은 파일을 3회 이상 되돌리면 즉시 중단 (해가 없다는 신호다)

■ 게이트 — 다음이면 **루프를 멈추고 Discord 선보고**
  1. 요구가 "적절히/자연스럽게" 로 끝나 판정 기준을 내가 정해야 한다
  2. 해석이 둘 이상이고 되돌리는 비용이 30분 초과
  3. 도메인을 몰라 "그럴듯한 것" 과 "맞는 것" 을 구별 못 한다
  4. 같은 오류를 2회 고쳤는데 재현된다
  → 보고: 시도 / 막힌 지점(재현 조건·수치) / 갈림길 2~3개와 비용 / 내 추천 1개
     **묻는 것은 하나로 좁힌다 — "A 인가 B 인가"**

■ 검증 (이걸 통과해야 "완료" 라고 말할 수 있다)
  1. {자동 테스트 명령} 초록
  2. {빌드 명령} 초록
  3. **실제로 실행해 재현** — 스크린샷 또는 수치
  4. 배포했다면 **번들 해시 대조**까지 (커밋 ≠ 배포)

■ 실패 프로토콜
  - 추측으로 고치고 "고쳤습니다" 라고 쓰지 마라. **계측값 없으면 보고 금지**
  - 재현 못 하면 "재현 실패" 로 보고 — 그것도 결과다
  - 부분 성공은 부분 성공이라고 쓴다

■ 보고 형식
  변경 요약 / 커밋 해시 / 검증 결과(수치) / **남은 문제(정직하게)**
════════════════════════════════════════════════════════════
```

## 5. 이 운용이 실제로 만든 차이

| 사건 | 이 원칙이 없었다면 | 실제 |
|---|---|---|
| 증거 복제 신고 5회 | 계속 "고쳤다" 보고 | Then 문장을 다시 써서 **테스트가 증상을 통과시키던 것**을 발견 |
| 3인칭 이동 버그 | 가설 1개만 고침 | 계측 강제로 **서로 다른 3개 원인** 분리 |
| 모델 교체 | 최신 모델로 갈아타고 끝 | 실측이 기각 — **되돌린 기록까지 문서에 남김** |
| CHANGED 뱃지 | 반나절 구현 후 유출 발견 | 적대적 검증 1회로 **구현 전에 기각**, 의미를 바꿔 살림 |
| 왕진 가방 에셋 | 라이선스만 보고 통과 | 렌더해서 눈으로 보고 **콘텐츠 규칙 위반** 발견 |

> 공통점: **싸게 먼저 틀리고, 비싸게 한 번만 확인한다.**
