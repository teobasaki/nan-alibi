- 날짜: 2026-08-09
- 상태: 채택
- 기준 커밋: `e7578fe` (워킹 트리 clean)
- 실측: `npx vitest run` → **14파일 178건 통과 1.31초** (05:13). 문서 4곳의 "136건", 과업 지시의 "161건"은 둘 다 만료된 숫자다.
- 배경: NAN 2026 마감 08-10 23:59 (잔여 약 43h). 제출물 5종 중 4종이 0%.

## 맥락

ADR 017 이 상황판을 세 각도로 놓았지만, 그 세 각도는 여전히 **오늘의 3단 껍데기**(`.cols { 25% 45% 30% }`, `src/style.css:60`)
안에서 탭으로 갈아 끼워질 뿐이다. 화면은 "정보를 비교하는 도구"가 아니라 "정보를 보관하는 서랍" 으로 읽힌다.

동시에 사용자가 두 가지를 요구했다 — 형사 탐정수첩(필수) 과 60 Seconds! 식 3D 이동.
그런데 코드에 실제로 쓸 수 있는 시간은 **10~15h이고 그것도 낙관**이다. 둘 다 하면 셋 다 못 끝낸다.

세 렌즈(마감·아키텍처·어필)로 3안을 적대 심사했다. 판정은 **아키텍처 8 / 어필 8 로 "펼친 수첩", 마감 7 로 "펼침면"** 이었다.
아래는 그 셋을 하나로 접붙인 계약이고, **각 안이 지적당한 fatal 을 접붙이기로 무력화한 것**이 이 문서의 핵심이다.

## 결정 — 펼침면의 우면은 항상 수첩이고, 좌면이 책상과 취조실 사이를 오간다

`.cols` 3단을 없애고 `.nb` 펼침면 2단으로 바꾼다. **추가가 아니라 교체다.**

| | 좌면 62% | 제본선 | 우면 38% (모드 무관 고정) |
|---|---|---|---|
| **책상** (`ui.active === null`) | 사건 면 — 세로 인덱스 탭 3장 | ║ | 위: 수사 일지 / 아래: 기록철 |
| **취조실** (`ui.active !== null`) | 3D 취조실 + 대화 | ║ | 위: 수사 일지 / 아래: 기록철 |

- 인덱스 탭 3장 = `alibiGrid()`(main.ts:450) · `placeGrid()`(main.ts:584) · `personSheets()`(main.ts:668).
  **DOM 은 한 줄도 안 고친다.** 부모 스코프 CSS(`.nb .agrid{…}`)로 재도색한다.
- 삭제: `suspectColumn()`(main.ts:229) · `situationBoard()` 껍데기(main.ts:544) · `.viewtabs` 가로 탭.
- 이동: `pendingBlock()`(main.ts:734)·`findingsBlock()`(main.ts:776)은 일지 안으로 흡수한다.

### 이 배치가 세 렌즈의 지적을 동시에 끄는 방식

**① 비교 면적이 줄지 않고 늘어난다.** 어필 렌즈가 두 안 모두에 같은 지적을 했다 —
격자 마지막 행 `확보 기록`(main.ts:519)은 기록 조회 목록으로 손을 넘기려고 존재하는데,
`board()`(main.ts:846)를 탭 뒤로 내리면 그 인계가 끊긴다. QA §5.4 가 지적한 축에서 순회귀다.
그래서 **기록철을 탭으로 내리지 않고 우면 하단에 고정**한다. 격자와 조회 목록은 오늘처럼 계속 동시에 보인다.
사라지는 것은 용의자 열 25% 하나뿐이고, 그 25%는 격자로 간다 — **격자 45% → 62%, 순증이다.**

**② 일지가 화면 절반을 먹지 않는다.** 어필 렌즈가 안 2에 던진 fatal("정보 구조가 문제라고 진단해 놓고 화면 절반을 회고에 줬는가")은
일지를 우면 **상단**으로 한정하는 것으로 끝난다. 일지는 새 정보를 주는 면이 아니라 내가 지출한 내역을 보는 면이다.

**③ 3D 호스트 폭이 두 모드에서 같아진다.** 오늘 3D 는 45% 안에서 mount 되고 렌더러는 mount 시점 `host.clientWidth` 로 크기를 잡는다(stage3d.ts:89-100).
새 배치에서 좌면은 두 모드 다 62% 라 폭이 상수다. 아키텍처 렌즈가 안 2의 62/38 재배치에 붙인 단서가 **오늘보다 안전한 쪽으로** 해소된다.
`roomEl` 영속 노드 규약(main.ts:113-131)과 `stage()` 조기 반환(main.ts:331-335)은 그대로 둔다.

### 색 — 밝은 종이를 쓰지 않는다 (안 1에서 접붙임)

레퍼런스는 밝은 펼침면이지만 여긴 불 꺼진 호텔(`--bg #16110f`)이다.
밝게 가면 `.agrid` 의 amber/red/green 대비 규칙을 전부 다시 잡아야 하고 인트로·취조실과 싸운다.
**가죽 표지 + 중간 명도 갱지**로 간다. 그러면 격자 색을 **한 줄도 안 고쳐도** 종이 위에 그대로 앉는다.
지질은 `src/style.css:367-377` 의 인라인 SVG `feTurbulence` 를 `baseFrequency` 만 바꿔 재사용한다 — **외부 에셋 0.**

### 손글씨 — 웹폰트를 쓰지 않는다

한글은 조서 본문이 LLM 이 쓴 글자라 부분 서브셋이 불가하다 → 자가 호스팅 0.7~1.5MB.
ADR 016 이 **정확히 이 함정을 이미 기록했다**("1명당 9.1MB … 60초 시연이 로딩으로 끝난다").
게다가 `CREDITS.md:17-20` 에 라이선스 `(확인 필요)` 4행이 이미 미결이다. 다섯 번째 미확인 자산을 마감 전에 만들지 않는다.

대체: 기존 명조(style.css:19) + 괘선 + `nth-child` ±0.4° 회전 + 잉크 농도 3단.
그리고 이 게임의 설정이 같은 답을 준다 — **조서를 받아 적는 것은 시스템이다**(crossref.ts:2). 본문이 활자인 게 맞다.
손글씨는 형사가 그은 몇 줄(모순 밑줄·여백 메모)에만 나타난다.

### 안 2 의 fatal 을 끄는 수정 — 일지는 "한 일"만 쓰고 "그래서 무엇이 되었나"는 안 쓴다

아키텍처 렌즈가 안 2 에 붙인 fatal: `journalLines()` 가 "남은 후보 3명" 을 **일지의 그 위치에** 쓰려면
그 시점의 `g.cards` 를 복원해야 하고, 그 복원은 `interview`·`presentEvidence`·`lookupEvidence` 가
카드에 무엇을 넣는지를 `src/ui/` 에서 **두 번째로 구현하는 일**이다. 밸런스가 바뀌면 타입 에러 없이 조용히 썩는다.

계약: **`journal.ts` 는 `candidatesFrom` 을 부르지 않고 `g.cards` 를 복원하지 않는다.**
남은 후보 수는 지금처럼 사건 면이 **현재 상태**를 읽어 그린다. 일지는 시간축이고 사건 면은 현재형이다 — 역할이 갈린다.

```ts
export interface JournalLine {
  round: number            // 소모한 조사 회차 (무료 행동은 직전 회차에 접힌다)
  text: string             // 1인칭 과거형 한 줄
  chip?: string            // '＋기록 1' · '＋진술 1' · '자물쇠 2/3'
  kind: 'get' | 'stamp' | 'miss' | 'idle'
  spent: boolean           // 이 줄이 조사 1회를 썼는가 (여백 눈금)
}
export function journalLines(tr: Trace, chats: Record<SuspectId, Chat[]>, c: CaseFile): JournalLine[]
```

**대사 복원은 새 저장소 없이 인덱스로 성립한다.** `doAsk`(main.ts:997→998)·`doPresent`(main.ts:1032→1035)가
둘 다 `mark()` 먼저 `chats` 나중으로 동기 append 하므로, 인물 `s` 의 n번째 `(ask|present)` ↔ `chats[s][n]` 이 맞는다.
**지금은 주석도 테스트도 없이 우연히 맞는 상태다** — 이 불변식을 `tests/journal.test.ts` 가 못 박는다.
안 지키면 일지는 오류가 아니라 **엉뚱한 이벤트에 엉뚱한 대사를 붙여 그럴듯하게** 렌더한다.

## 3. 검증 방법

**테스트로 고정할 수 있는 것** (`tests/journal.test.ts`, 커밋 게이트가 강제):

- 조사 1회 소모 = `spent:true` 줄 정확히 1개. `connect`·`view` 는 `spent:false`.
- **정렬 불변식**: 인물 `s` 의 n번째 `(ask|present)` 이벤트 ↔ `chats[s][n]`. 폴백(조사 환불) 경로에서도 어긋나지 않는다.
- 폴백 `ask` 는 회차를 올리지 않는다 (조사가 환불되므로).
- `journalLines()` 는 `candidatesFrom`·`g.cards` 를 참조하지 않는다 — import 부재를 테스트로 못 박는다.
- 심문 전 인물의 진술이 일지에 새지 않는다 (ADR 017 이 표에 건 것과 같은 검사).

**눈으로 봐야 하는 것** (배포본, 리허설 3회로 겸함):

- 갱지 위에서 `.agrid` 의 amber/red/green 이 여전히 읽히는가 (색을 안 고친다는 전제의 유일한 위험).
- 탭 전환·페이지 넘김 애니메이션이 **매 렌더 다시 돌지 않는가**. `render()` 가 `app.replaceChildren()` 로 트리를 통째로 간다 —
  인장이 정확히 이 사고를 겪고 `ui.stamped` Set(main.ts:497 부근)으로 막았다. 같은 가드를 `ui.flipped` 로 둔다.
- 900px 이하에서 펼침면이 단면으로 접히고 일지가 네 번째 탭으로 내려가는가.
- **E1(사람의 실제 플레이 시간)** — 완료기준 A~E 중 유일한 미검증 항목이다. 리허설 3회가 곧 사람 플레이 3판이므로 시각만 재면 닫힌다. 별도 일정으로 잡으면 순수 낭비다.

## 4. 버린 대안

### ✕ 3D 이동·오브젝트 상호작용 (안 3 "손전등", 12~15h) — 전면 폐기

근거가 취향이 아니라 파일이다.

1. **걷기 클립이 0개다.** 배포되는 GLB 9개 전부 `animations: []`. `src/` 전체에 `AnimationMixer`·`Raycaster` 문자열 0건.
2. **자기 문서가 틀렸다.** `docs/decisions/016-3D-도입.md:32` 와 `stage3d.ts:14` 가 둘 다 "오토리깅이 주는 클립은 걷기·달리기뿐" 이라 적어 놨는데,
   `assets-src/security.mvrigged.glb` 의 유일한 클립은 **키프레임 1개짜리 정지 포즈 스냅샷**이다.
   이 문장을 믿고 착수하면 4시간을 태운 뒤에 알게 된다. **이 반증 자체가 이번 조사의 최대 산출물이고, AI 활용 기술 PDF §4 에 13번째 항목으로 들어간다.**
3. **리그가 세 규약으로 갈라져 있다** (Meshy 24본 / CharacterCreator 102·104본 / Sketchfab 89본). 한 벌의 뼈 이름으로 8명을 못 움직인다.
4. **걸을 공간이 없다.** 취조실 실측 3.44m × 3.73m, 한가운데 테이블(stage3d.ts:317-326). 보행 링 0.5~1.0m. 코드 문제가 아니라 에셋 문제다.
5. **집을 것을 못 고른다.** `room.opt.glb` 노드 5개가 전부 이름 `defaultMaterial`.
6. **넣으면 지금 있는 화질을 반납한다.** `docs/design-review.md` 우선순위 1 이 카메라를 2.05m→1.35m, FOV 46°→37° 로 당긴 이유가
   "뭉개진 손가락·비정상적으로 곧은 팔" 을 프레임 밖으로 미는 것이었다. 전신 상시 노출 + 클립 0 = **미끄러지는 인형**.
7. 어필 렌즈의 fatal: **"어필 전체를 제출 불가일 수 있는 단 하나의 에셋에 건다."** `room.opt.glb` 는 `CREDITS.md:17` 의 `(확인 필요)` 첫 줄이다.
   지금은 사진 폴백이 달린 배경이라 조용히 빠져도 게임이 산다. 수색층으로 만들면 ND/NC 판정 시 **배경보다 먼저 죽는다.**
8. 아키텍처 렌즈의 fatal: **"178건 무손상은 경계를 지킨 증거가 아니라 게이트가 새 코드를 안 본다는 증거다."**
   정사영 카메라·클리핑 평면·AABB 충돌·SpotLight 판정 전부 jsdom 도달 불가 — 15시간짜리 안이 커밋 게이트에 1건도 추가하지 않는다.
   그리고 자기모순: "roomEl 을 공유한다" 와 "stage3d.ts 0줄" 이 양립하지 않는다 (`mount()` 는 진입 시 남의 캔버스를 지운다, stage3d.ts:107-109).

**대신 취조실이 얻는 것:** 이동이 아니라 **극적 지위**다. 갱지에서 어두운 방으로 넘어가는 왕복이 게임의 박자가 된다.
기존 `doorOpen` 연출은 이미 그 순간을 갖고 있고, 지금은 3단 레이아웃 안에서 그 극성이 죽어 있다. **0h.**

### ✕ 상황판을 남기고 수첩을 네 번째 화면으로 추가

가장 쉬운 길이고 가장 나쁜 길이다. 같은 진술이 격자·상황판·수첩에 **세 번** 나온다.
이 파일은 그 중복을 이미 두 번 지웠다(main.ts:258 "여기 또 적으면 같은 문장이 화면에 세 번 나온다", main.ts:503 부근).
지금 정하지 않으면 작업 후반에 되돌린다. **대체지 추가가 아니다.**

## 구현 순서 — 각 단계가 그 자체로 출하 가능하다

각 단계 끝에서 커밋한다. 중간에 시간이 다 되면 **거기까지가 완성품**이다.

### 0단계 — 코드보다 먼저 (1.25h) · 08-09 09:00

- **`CREDITS.md:17-20` 라이선스 4건.** 누락은 규정상 **선발 취소 사유**다. 코드보다 앞선다. (1h)
- **DRACO 자가 호스팅.** `node_modules/three/examples/jsm/libs/draco/gltf/` → `public/draco/`,
  `setDecoderPath('/draco/')` — **두 곳 다**(stage3d.ts:137·218). 안 하면 녹화 중 회선이 흔들릴 때 사진 폴백이 영상에 찍힌다. (0.25h)
- **팀원에게 오늘 아침 던질 것 하나:** 제출물 5번(팀원 롤 기술서). `docs/QUESTIONS.md:10-13` 의 Q2 가 아직 미해결 한 줄뿐이고,
  2인 팀이라 누락 = 심사 제외다. 내가 못 줄이는 유일한 항목이라 미루면 마지막 날의 순수 대기 시간이 된다.

**정지 시 상태:** 오늘 화면 그대로 + 규정 리스크 2건 제거 + 녹화 안전. 그 자체로 이득이다.

### 1단계 — 펼침면 골격 (2.5h) · 게이트 08-09 14:00

- `.cols` → `.nb { grid-template-columns: 62% 38% }`. 제본선 1개.
- 좌면: 세로 인덱스 탭 3장 + `alibiGrid`/`placeGrid`/`personSheets` **DOM 무수정** 삽입.
- 우면: 상단에 빈 일지 통(자리만) + 하단에 `board()` 그대로.
- `suspectColumn()` 삭제. **그 전에** `main.ts:484`·`687` 의 `choose` 에 `hush(); stopVoice()` 를 넣는다 —
  지금 그 정리 코드는 `main.ts:242`(용의자 카드) 한 곳에만 있고, 삭제하면 그 진입로가 사라져
  **인물 전환 시 이전 TTS 와 말풍선이 겹쳐 도는 상태로 녹화된다.** 한 줄짜리 수정인데 빠뜨리면 영상이 죽는다.
- `ui.view` 전환 가드(`ui.flipped`)를 이 단계에 넣는다. 나중에 넣으면 애니메이션이 매 행동마다 다시 돈다.

**정지 시 상태:** 오늘과 같은 정보를 더 넓은 격자로 보는 2단 화면. 종이는 아직 아니지만 **출하 가능하다.**

### 2단계 — 종이 (1.5h)

- 갱지 배경 + `feTurbulence` 지질 + 괘선 + 가죽 표지 + 제본선 그림자.
- 탭 dog-ear: 미대조가 0보다 크면 대조표 탭 귀퉁이가 접힌다(`clip-path`). 연결은 조사를 소모하지 않으므로 접힌 귀는 항상 **공짜 다음 수**를 가리킨다.
- `play('paper')` 를 탭·페이지 전환에 건다 — `src/ui/sound.ts:17`, main.ts:559 에서 이미 쓰는 중. **신규 사운드 0.**

**정지 시 상태:** "수첩이 화면이다" 가 성립한다. 영상에 담기는 최소 상태.

### 3단계 — 일지 (2.5h) · 게이트 08-09 22:00

- `src/ui/journal.ts` + `tests/journal.test.ts` 먼저 쓴다(§3 의 불변식부터).
- 우면 상단 렌더 + 여백 눈금(`spent` 줄과 같은 높이) + 인라인 칩.
- 상단바 조사 pip(main.ts:204-206) 삭제 — 여백 눈금이 같은 정보를 더 좋게 말한다. 남기면 중복이다.
- `findingsBlock()`·`pendingBlock()` 을 일지로 흡수. 모순은 별도 목록이 아니라 일지 안의 인장이 된다.

**정지 시 상태:** 계약의 본체가 완성된다. **여기까지가 이 ADR 의 최소 성공선이다.**

### 4단계 — 동시 필기 (1h)

- 심문 모드에서 좌면을 3D 취조실로 바꾼다. 우면은 손대지 않는다(이미 고정이라 자동으로 성립한다).
- 대사가 도착하면 말풍선과 동시에 우면 일지에 조서 한 줄이 적힌다.
- **`stage3d.ts` 는 0줄 고친다.**

**정지 시 상태:** 영상의 핵심 컷이 생긴다 — 왼쪽에서 사람이 말하고, 오른쪽에서 형사가 받아 적고, 눈금이 하나 그어진다.
**AI 가 만든 것과 코드가 계산한 것이 한 프레임 안에 나란히 보인다.** 대시보드를 열지 않고 그 명제를 보여주는 방법이고,
지금 그 대시보드는 Supertone 줄이 빨간 상태라 여는 순간 결함도 같이 찍힌다.

### 5단계 — 마감 여유가 있을 때만 (0.5h)

- `TraceEvent.connect` 에 `ev`·`cid` 두 필드 추가(journey.ts:38, 호출 2곳). 지금은 `hit` 뿐이라 **실패한 연결이 무엇이었는지 복원 불가**다.
  로그 필드일 뿐 규칙 계산이 아니므로 engine 경계 무손상. `tests/journey.test.ts` 1줄 갱신.
- `profile(ui.journey).note`(journey.ts:102-131)를 마지막 페이지 여백에 연필 메모로. 지금은 오답 진단(main.ts:1249)에만 나온다 —
  **판이 끝난 뒤가 아니라 판 중에** 나와야 값이 있다.

### 코드 프리즈 이후 (08-10 12:00~)

`docs/DEMO.md` §2 재작성 **3h + 재촬영 2h**. 10행 대본이 전부 물리 화면 위치에 묶여 있어("오른쪽 CCTV", "왼쪽 보드에서 카드 두 장 연달아")
