# ADR 021 — 걷기 리그의 축을 런타임에서 되돌리고, 이동을 카메라 기준으로 바꾼다

- 날짜: 2026-08-09
- 상태: 채택
- 관련: [ADR 019](019-경찰서-자유이동.md)

## 배경

탐색 모드를 직접 플레이해 보고 네 가지가 보고됐다.
① 무릎이 뒤로 꺾인다 ② 사람 형체가 공중에 떠 있다 ③ 방향키가 이상한 방향으로 먹는다
④ 수첩 열고 전환이 성의 없다.

## 결정 1 — 다리 애니메이션 축을 런타임에서 되돌린다

`scripts/retarget.py` 가 Copy Rotation 을 `LOCAL_WITH_PARENT` 로 건다. 이 공간은 회전을
**각 본의 rest 축 성분 그대로** 복사하고, 블렌더는 두 리그의 rest 축 차이를 보정하지 않는다.
(그 파일 주석이 "블렌더가 알아서 흡수한다" 고 적고 있었다 — **틀렸다.** 고쳐 놨다.)

이 리그는 **다리 본 8개만** Mixamo 대비 자기 축(Y) 기준 180° 롤돼 있다
(몸통·팔·머리 15개는 정렬). 180° Y 롤은 X 와 Z 를 뒤집으므로
`(x, y, z, w) → (-x, y, -z, w)` 로 되돌린다 (`explore3d.ts` 의 `unrollLegs`).

### 어떻게 확인했나 — 세 가지가 같은 결론
1. 무릎 **굽힘축**이 월드에서 `(-1, 0, 0)`. 정면 +Z 인 인물에서 -X 굽힘은 정강이를 **앞으로** 접는다.
2. **팔꿈치**를 같이 재니 축 부호가 무릎과 **같았다**. 사람은 둘이 반대로 굽는다 — 하나가 뒤집힌 것이고,
   팔은 멀쩡했으니 다리다.
3. 정면은 `headfront` 본으로 확정 (머리→headfront 가 +Z).

### 어디에 거는가 — **rest 기준 delta 에 건다** (여기서 한 번 틀렸다)
처음엔 트랙의 **원 회전값**에 `(-x, y, -z, w)` 를 걸었다. `security` 로 재니 멀쩡해 보여서
그대로 넣었는데, 다른 모델로 확인하니 틀렸다:

| 모델 | 원 회전값에 걸기 | **rest delta 에 걸기** |
|---|---|---|
| security | 역꺾임 0 | 역꺾임 0 |
| **investor** | **역꺾임 59프레임 그대로 · 발목이 1.3m 로 솟음** | **역꺾임 0** |
| secretary | 역꺾임 0 (발목 Z -0.58~0.21, 한쪽 쏠림) | 역꺾임 0 (-0.45~0.31 균형) |

어긋난 것은 **"rest 에서 얼마나 움직였나"** 를 표현한 축이지 최종 자세가 아니다.
원 회전값을 뒤집으면 rest 자세까지 같이 뒤집혀, rest 가 우연히 180° 에 가까운 모델에서만
맞는다. **한 모델로 확인하고 넘어가면 안 된다** — 이 프로젝트가 모델 선택에서 배운 것과 같다(ADR 020).

### 버린 대안
- **무릎 두 개만 X 오일러 뒤집기** — 무릎은 펴지는데 **발목이 -0.53 ~ 0.10 으로 뒤로만 끌린다.**
  끌면서 걷는 것처럼 보인다. 다리 전체를 되돌리면 -0.42 ~ 0.32 로 앞뒤가 균형 잡힌다. 재서 갈랐다.
- **리타게팅 다시 하기** — 그게 정답이지만 Blender 가 필요하고 제출이 하루 남았다.
  런타임 보정은 두 줄이고 원본 GLB 를 건드리지 않는다. `retarget.py` 에 결함을 적어 뒀다.

## 결정 2 — 이동을 카메라 기준으로 바꾼다

키 입력이 월드축이었다. 탑다운 카메라가 아이소메트릭(`CAM_OFF=(9,12,9)`)이라 실측하면:

| 키 | 화면 각도 (0°=위) | 기대 |
|---|---|---|
| W | **56°** | 0° |
| D | **124°** | 90° |
| S | **236°** | 180° |
| A | **304°** | 270° |

게다가 **어긋난 양이 균일하지도 않다**(W/S 56°, A/D 34°) — 카메라가 41.9° 내려다봐서
화면 세로축이 눌리기 때문이다. 그래서 사람이 "한쪽으로 밀린다" 고 학습해 보정할 수조차 없다.

카메라의 지면 투영 전방/우측 벡터로 옮겼다. 수정 후 실측: W 0° · D 95° · S 180° · A 270°.

**1인칭은 다르게 잡았다.** 좌우를 게걸음으로 두면 몸이 그쪽을 보고 돌아 시야가 휘둘린다
(몸의 방향이 곧 눈의 방향이라서). 그래서 1인칭에서 좌우는 **회전**이다.

### 버린 대안
- **카메라를 정면(0, h, d)으로 돌리기** — 방향 문제는 사라지지만 아이소메트릭 특유의
  공간감이 사라지고, 벽이 시야를 가린다. 카메라를 바꾸느니 입력을 바꾼다.

## 결정 3 — 발을 바닥에 붙인다

모델마다 원점이 다르다. `position.y = 0` 으로 두니 다섯 중 하나가 **90cm 공중에 떠 있었고**
나머지는 10~28cm 묻혀 있었다. 크기를 맞춘 뒤 **가장 낮은 점**을 재서 내린다(`groundIt`).
스킨드 메시라 뼈를 적용해 재야 한다 — 안 그러면 노드 스케일 때문에 값이 100배 틀린다(ADR 019 참고).

## 결정 4 — 3D 수첩과 DOM 수첩을 **겹쳐서** 넘긴다

예전엔 3D 가 끝난 **뒤** DOM 이 시작해 두 개의 다른 물건으로 보였다.
이제 `showJournal(onHandoff)` 이 3D 가 걷히기 시작하는 순간 콜백을 부른다.
실측: **0.89초에 넘기고 0.45초 동안 겹친다**(3D 1.00 → 0.06 하는 동안 DOM 이 펼쳐진다).

같이 손본 것:
- DOM 펼침 각도 88° → **34°**. 3D 가 이미 펼쳐진 수첩을 보여줬는데 여기서 90° 로 접었다 펴면
  모양이 어긋나 두 개로 읽힌다.
- 3D 앞 35% 동안 **조명이 올라온다**(스탠드가 켜지듯). 모델에 애니메이션이 없어도 정지 화면이 안 된다.
- 콜백은 에셋이 없거나 못 그리는 상황에서도 **반드시 한 번** 불린다 — 안 그러면 게임이 시작되지 않는다.
