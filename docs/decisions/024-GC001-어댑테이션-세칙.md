# ADR 024 — GC-001 어댑테이션에서 계약과 달라진 세부 4건

- 날짜: 2026-08-10
- 상태: 채택 (구현 커밋 8ef3c0e · 923bd0d)
- 관련: GC001 어댑테이션 계약(docs/content/GC001-엔진-어댑테이션-계약.md), ADR 023

계약 서두의 지시("구현하며 세부가 달라지면 ADR에 이유를 남긴다")에 따른 기록이다.
계약 문서 자체는 메인 세션 소유라 손대지 않았다 — 차이는 전부 여기에 있다.

## 1. 자백 오버라이드의 착지점: confessions.ts 훅이 아니라 `CaseFile.ending`

계약 §2는 "confessions.ts 에 케이스 오버라이드 훅"이라 적었다. 구현은
`CaseFile.ending { confession, beats }` 선택 필드로 했다 — 자백과 5단계 재구성을
**사건 데이터가 직접 소유**하면 훅의 키(무엇으로 케이스를 식별하나) 문제가 사라지고,
main.ts 는 "있으면 그것, 없으면 페르소나 템플릿" 한 줄이 된다.

- 버린 대안: confessions.ts 에 caseId 키 테이블 — CaseFile 에는 id 가 없고
  seed(1)는 시드 풀과 충돌한다. 식별자를 새로 파느니 데이터를 사건에 두는 게 싸다.

## 2. `Evidence.note` 필드 추가 (계약에 없음)

gc001 의 동기 정황(해임 통지 출력)·규칙 명시(위치 비고정, 2분 거리)는
시각·장소·인물로 표현되지 않는다 — 정본의 Evidence 는 서술형 구조화 내용을 갖지만
엔진의 Evidence 는 좌표뿐이었다. 카드 '비고' 행 하나로 얹었다.
생성 사건은 note 를 쓰지 않으므로 호텔 출력은 바이트 단위로 같다.

## 3. 조회 버튼 라벨 '정황 확인' 신설 + 예산 0 무료 조회 버튼 활성화

- 인물을 담지 않은 범행 시각 기록(E5 위치 비고정 통화)에 '후보 소거' 라벨이 붙었다 —
  거짓말이다. subjects 유무로 '후보 소거/정황 확인'을 가른다. 이것이 조회 전
  정보 노출인가: 정본이 E5 를 "위치를 고정하지 않는 통화(명시)"로 정의하므로
  노출이 아니라 정의의 전달이다. 호텔 사건은 범행 시각 기록 전부에 인물이 있어 무변화.
- **예산 0 에서 해금 기록 버튼까지 비활성이던 버그**를 이 작업에서 발견했다.
  엔진은 무료 조회를 허용하는데(ADR 023 §2) 화면이 막아 통찰 보너스가 도달 불가였다 —
  호텔 사건도 같은 버그였다. 보드 버튼과 3D 픽 둘 다 "requires>0 이면 무료"로 정정.

## 4. V3 완화와 결정적 못박기의 일반화 (계약 §2 '주의'의 이행)

"결정적 기록 = 범행 시각·현장" 은 호텔 생성기의 습관이었다. V3 는
"결정적 1건 + 그 subjects 가 범인 한 명"만 검사하고, 후보 계산(solver·bots)은
decisive 플래그로 슬롯 무관 못박기를 한다. 생성 사건의 슬롯·장소 습관은
tests/caseGen.test.ts 가 계속 잠근다 — 검증기가 느슨해진 것이 아니라
법칙과 습관을 제자리에 나눠 놓은 것이다.

## 기타 (계약 범위 내 선택)

- E5 subjects 는 계약의 두 선택지 중 빈 배열 — [배지호]로 두면 V2(물증=진실)와 충돌.
- kindLabels 에 call→'통화 기록' 추가 (Partial 이 허용) — '통화 기지국 기록'은 호텔 어휘.
- 재현 영상은 월드 사건에서 재생하지 않는다 — 자막이 호텔 전용(카드키·12층)이다.
- 페르소나 배정: 류나린=calculating(통제형), 배지호=timid(동요), 문소라=emotional(불안),
  도율=authoritative(방어), 김하늘=egocentric(회피). timid+guilty 동시 배정 금지 준수.
