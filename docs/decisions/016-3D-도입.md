# ADR 016 — Three.js 3D 심문석 도입

## 결정
심문 화면의 인물 자리를 **3D 취조실**로 바꾼다. 모델은 Meshy text-to-3d + 오토리깅.

## 실측값 (추정이 틀렸다)
| 항목 | 추정 | **실측** |
|---|---|---|
| 캐릭터 메시(preview+refine) | ~20 | **30** |
| 오토리깅 | 5 | **5** |
| 1명당 | ~25 | **35** |
| 8명 | ~200 | **280** |

추정이 40% 낮았다. 문서의 예시값(20)을 그대로 믿은 탓이다 — 잔액 차이로 재고 나서 정정했다.

## 용량 — 이게 진짜 문제였다
리깅 출력이 **1명당 9.1MB**. 8명이면 73MB 로 60초 시연이 로딩으로 끝난다.
`gltf-transform optimize --texture-size 768 --texture-compress webp --compress draco`
로 **0.34MB** 가 됐다 (27배). 8명 전부 실어도 3MB 미만이다.

폴리곤 감축(`--simplify`)은 0.10MB 까지 가지만 스킨 가중치를 건드려 리그가 상할 수 있어
기본은 끈다. 원본 `.rigged.glb` 는 gitignore 하고 `.opt.glb` 만 커밋한다 —
설정을 바꿔 다시 뽑을 때 크레딧을 재차 태우지 않기 위해 디스크에는 남긴다.

## 안전 장치 — 이게 없으면 도입하면 안 됐다
마감 이틀 전이다. 3D 는 **덧붙이기만** 한다:
- WebGL 없음 / 모델 없음 / 로드 실패 → `mount()` 가 `null` 을 돌려주고 **2D 사진으로 폴백**
- `three` 는 동적 import — 메인 번들 54KB 유지, 3D 청크(188KB gzip)는 심문 시작 때만
- 게임 규칙·엔진·테스트 120개는 한 줄도 안 건드렸다

## 애니메이션은 절차적으로
오토리깅이 주는 클립은 **걷기·달리기뿐**이라 심문 장면에 쓸 데가 없다.
뼈를 직접 흔든다 — 호흡(압박이 오르면 빨라지고 얕아진다), 말할 때만 사는 고개,
압박 60 이상에서 미세한 떨림. 조명도 함께 붉게 조여든다.
상태에 반응하므로 고정 클립보다 이 게임에 맞고, 크레딧이 0이다.

## 카메라 — 첫 배선의 실패
전신을 담았더니 얼굴이 20px 이 됐다. 얼굴을 보여주려고 3D 를 넣었는데 그게 안 되면
넣은 의미가 없다. **눈높이에서 가슴 위로** 바짝 붙이고, 벽을 당기고,
스포트라이트 하나 + 반사광 0.18 로 낮췄다. ACES 톤매핑이 없으면 하이라이트가 타서
플라스틱처럼 보인다.

## 버린 대안
- **블렌더로 자체 제작**: 포토리얼 인체는 스컬프팅·리토폴로지·텍스처 페인팅이라
  스크립트로 안 된다. 프리미티브 조합은 마네킹이 나온다. 다만 블렌더는
  **최적화와 아이들 애니메이션 저작**에는 맞는 자리다 (아직 미사용).
- **취조실 소품 생성**: 어두운 방은 상자 몇 개와 조명 하나다. Three.js 프리미티브로
  충분하고 크레딧 0 이다. 돈은 얼굴에 쓴다.
