# ADR 016 — Three.js 3D 심문석 도입

## 결정
심문 화면의 인물 자리를 **3D 취조실**로 바꾼다. 모델은 Meshy text-to-3d + 오토리깅.

## 실측값 (추정이 틀렸다)
| 항목 | 추정 | **실측** |
|---|---|---|
| 캐릭터 메시(preview+refine) | ~20 | **30** |
| 오토리깅 | 5 | **5** |
| 1명당 | ~25 | **35** |
| 8명 | ~200 | **280** |

추정이 40% 낮았다. 문서의 예시값(20)을 그대로 믿은 탓이다 — 잔액 차이로 재고 나서 정정했다.

## 용량 — 이게 진짜 문제였다
리깅 출력이 **1명당 9.1MB**. 8명이면 73MB 로 60초 시연이 로딩으로 끝난다.
`gltf-transform optimize --texture-size 768 --texture-compress webp --compress draco`
로 **0.34MB** 가 됐다 (27배). 8명 전부 실어도 3MB 미만이다.

폴리곤 감축(`--simplify`)은 0.10MB 까지 가지만 스킨 가중치를 건드려 리그가 상할 수 있어
기본은 끈다. 원본 `.rigged.glb` 는 gitignore 하고 `.opt.glb` 만 커밋한다 —
설정을 바꿔 다시 뽑을 때 크레딧을 재차 태우지 않기 위해 디스크에는 남긴다.

## 안전 장치 — 이게 없으면 도입하면 안 됐다
마감 이틀 전이다. 3D 는 **덧붙이기만** 한다:
- WebGL 없음 / 모델 없음 / 로드 실패 → `mount()` 가 `null` 을 돌려주고 **2D 사진으로 폴백**
- `three` 는 동적 import — 메인 번들 54KB 유지, 3D 청크(188KB gzip)는 심문 시작 때만
- 게임 규칙·엔진·테스트 120개는 한 줄도 안 건드렸다

## 애니메이션은 절차적으로
오토리깅이 주는 클립은 **걷기·달리기뿐**이라 심문 장면에 쓸 데가 없다.
뼈를 직접 흔든다 — 호흡(압박이 오르면 빨라지고 얕아진다), 말할 때만 사는 고개,
압박 60 이상에서 미세한 떨림. 조명도 함께 붉게 조여든다.
상태에 반응하므로 고정 클립보다 이 게임에 맞고, 크레딧이 0이다.

## 카메라 — 첫 배선의 실패
전신을 담았더니 얼굴이 20px 이 됐다. 얼굴을 보여주려고 3D 를 넣었는데 그게 안 되면
넣은 의미가 없다. **눈높이에서 가슴 위로** 바짝 붙이고, 벽을 당기고,
스포트라이트 하나 + 반사광 0.18 로 낮췄다. ACES 톤매핑이 없으면 하이라이트가 타서
플라스틱처럼 보인다.

## 버린 대안
- **블렌더로 자체 제작**: 포토리얼 인체는 스컬프팅·리토폴로지·텍스처 페인팅이라
  스크립트로 안 된다. 프리미티브 조합은 마네킹이 나온다. 다만 블렌더는
  **최적화와 아이들 애니메이션 저작**에는 맞는 자리다 (아직 미사용).
- **취조실 소품 생성**: 어두운 방은 상자 몇 개와 조명 하나다. Three.js 프리미티브로
  충분하고 크레딧 0 이다. 돈은 얼굴에 쓴다.

## 앉은 자세 — 블렌더가 실제로 값을 한 자리
Meshy 오토리깅은 **A포즈로 선 캐릭터**를 준다. 취조실에 서 있는 사람은 어색하다.
블렌더 헤드리스로 리깅된 GLB 를 받아 앉은 자세로 굳혀 다시 내보낸다
(`scripts/pose-seated.py` + `scripts/pose-all.mjs`, 빌드에 물려 둠).

**팔 각도는 눈대중이 아니라 탐색으로 찾았다.** 처음엔 손이 가슴 앞에서 꼬였다 —
glTF 임포트된 뼈의 로컬 축을 추측했기 때문이다. 위팔·아래팔 3축을 격자 탐색하면서
"손이 무릎 위에 오는" 조합을 거리 최소화로 골랐다(왼손↔왼무릎 0.13m).
Meshy 리그는 24본 Mixamo 계열 이름이라 8명이 같은 값을 공유한다.

MCP 로 대화하며 한 명씩 잡지 않고 **스크립트 파일로 만든 이유**: 모델을 다시 뽑거나
자세를 고칠 때마다 처음부터 다시 해야 하고, 8명에 같은 값을 적용할 수 없다.

## 카메라 — 상수를 두 번 틀리고 나서 실측으로
눈높이를 상수로 박았다가 두 번 틀렸다:
- 1.56(선 사람) → 앉은 모델에서 **정수리**를 봤다
- 1.25(앉은 사람) → **가슴**을 봤다

모델이 8개인데 상수는 언제든 다시 틀린다. **머리 뼈의 월드 좌표를 읽어** 그 앞에
카메라와 스포트라이트를 놓도록 바꿨다. 선 모델이든 앉은 모델이든 같은 코드가 맞춘다.

## 블렌더에 대한 정정
처음에 "블렌더로 최적화와 애니메이션을 하겠다" 고 했는데, 그 둘은 결국 다른 데서 해결됐다 —
압축은 `gltf-transform`(27배), 아이들은 Three.js 절차적 구동(압박 수치에 반응).
**블렌더가 실제로 값을 한 것은 앉은 자세 하나다.** 도구를 먼저 정하고 쓸 데를 찾으면
이렇게 된다. 다만 그 하나는 다른 방법으로는 안 되는 것이었다.

## 최종 (8명 완료)
- 생성: 8명 × 35크레딧 = **245크레딧** 소모, 잔액 1247
- 용량: 원본 70.3MB → 최적화 **2.64MB** (27배)
- 8개 모두 배포본에서 200 응답 확인
- 카메라 실측 배치가 서로 다른 체형(보안 팀장·투자자 등)에서 모두 얼굴을 잡는 것 확인

`.opt.glb` 만 커밋한다(2.7MB). 원본 `.rigged.glb`·`.seated.glb`(70MB)는 gitignore 하되
디스크에는 남긴다 — 설정을 바꿔 다시 뽑을 때 245크레딧을 재차 태우지 않기 위해서다.

## 취조실 에셋 · 착석 · 연출 (2·3번)

### 방
사용자가 구한 취조실 GLB(탁자·의자·갓등·편면거울·문)로 자작 상자 씬을 전부 교체했다.
39MB → **0.68MB**. 원본은 `assets-src/` 로 빼고 gitignore — Cloudflare Pages 는
25MB 초과 파일을 거부해 배포가 한 번 실패했다.

배율 **1.9** 는 역산이다: 이 모델의 테이블 상판/의자 좌면 높이 비가 1.63 인데
실제 가구가 1.64 라, 테이블이 0.74m 가 되는 배율을 구했다.

### 착석 — 축 변환이 관건이었다
의자 좌표는 방 GLB 를 블렌더로 열어 좌면 높이 버텍스를 XY 군집화해 뽑았다
(원본 x≈-0.28 에 4개, x≈0.42 에 2개, 테이블 긴 축은 Y).

**블렌더는 Z-up, three.js 는 Y-up** 이다. glTF 의 (x,y,z) 가 블렌더에서 (x,-z,y) 로
들어오므로 블렌더 (x,y) → three (x,·,-y). 여기에 배율을 곱한다. 이 변환을 빼먹으면
사람이 벽 속이나 공중에 선다.

카메라는 맞은편 의자 자리다. 처음 1.5m 로 뒀더니 방의 갓등이 머리 위에 걸려 갓이 화면
절반을 덮었다 — 2.05m 로 물러서고 측면 0.34m 비껴 등을 화면 위 구석에 남겼다.

### 연출
- **말풍선**: 3D 인물의 머리 옆. 얼굴을 화면 좌표로 투영해 매 프레임 따라간다.
  심문 중 눈은 아래 로그가 아니라 얼굴에 가 있다.
- **삐걱**: 등이 진폭 최대에 닿는 순간마다(3.2초 간격 이상) 탁자가 삐걱인다 —
  소리와 그림이 같은 박자를 탄다. 톱니파를 느리게 미끄러뜨려 '뒤틀림' 을 만든다.
- **방이 열린다**: `clip-path` 로 문틈이 벌어지듯 드러나고 걸쇠 소리가 난다.

### 함정 둘
- `host.replaceChildren()` 로 3D 호스트를 비웠더니 거기 얹어 둔 **말풍선까지 지워졌다.**
  캔버스만 골라 치우도록 고쳤다.
- 말풍선 배선을 `doPresent` 에만 넣고 `doAsk`(심문)에 빠뜨렸다. 정작 말풍선이 제일 필요한
  쪽이 심문이다.

### 측정 환경에 대한 정정
"렌더 루프가 죽었다" 고 단정하고 한참 쫓았는데, 원인은 **내 브라우저 두 개가 모두
페이지를 `document.hidden = true` 로 보고**하는 것이었다. 그 상태에서 브라우저는
rAF 를 아예 주지 않는다 — 그 자리에서 만든 순수 rAF 루프도 1초에 0프레임이었다.
사용자가 실제 화면에서 움직임을 확인해 줬다.

다만 그 과정에서 **진짜 버그 하나는 잡았다**: 정지를 막으려 넣은 감시견의 `lastFrame` 을
`tick()` 정의보다 뒤에 선언해 TDZ 로 `mount()` 전체가 실패하고 있었다.
**정지를 막으려던 코드가 3D 를 죽였다.**

## 삐걱 소리 — 안 들린 이유
41~58Hz 톱니파를 **320Hz 밴드패스(Q=7)** 에 통과시켰다. 통과대역이 기음보다 한참 위라
거의 아무것도 통과하지 못했고, 게인도 0.075 로 너무 작았다.

삐걱임의 정체는 **stick-slip** — 붙었다 미끄러지길 반복하며 진폭이 잘게 떨리는 것이다.
LFO 로 게인을 흔들지 않으면 그냥 낮은 웅웅거림이다.

`OfflineAudioContext` 로 두 레시피를 렌더해 실제 진폭을 쟀다:

| | peak | RMS |
|---|---|---|
| 옛 레시피 | 0.016 | **0.0016** (사실상 무음) |
| 새 레시피 | 0.328 | **0.0386** (24배) |

**소리는 귀로 못 들어도 잴 수 있다.** 안 들린다는 보고를 받고 추측으로 키우는 대신
렌더해서 숫자를 봤어야 했다.

## 몸동작 — 리깅을 실제로 쓴다
얼굴만 흔들면 인형이다. 말할 때 아래팔이 들썩이고(앉아서 말하는 사람이 하는 것)
어깨·목이 그 리듬을 받는다. 제스처 세기는 부드럽게 따라가게 했다 — 켜고 끌 때
툭 끊기면 그 자체가 인형처럼 보인다.

## 룸 인터랙션 — 좁게 허용한다
휠로 다가가고 끌어서 둘러본다. 다만 **자유 궤도는 주지 않는다** — 벽 밖으로 나가거나
뒤통수를 보게 되면 "취조하는 자리" 라는 전제가 깨진다.
좌우 ±20°, 상하 ±11°, 거리 0.55~1.45배로 묶었다.

## 멀티뷰 — 인물 품질의 진짜 원인

사용자 지적: "인물 생성 시 옆·앞·뒤 등 다양한 모습을 만들어야 하는 것 아니냐."
맞았다. 정면 한 장만 주면 Meshy 는 **옆·뒤를 지어낸다.**

배포본을 열어 실측한 결과가 세 증상을 모두 설명했다:

| 증상 | 원인 (실측) |
|---|---|
| 디테일 부족 | 텍스처를 2048 → **768** 로 줄였다. 이 한 장이 몸 전체 아틀라스라 얼굴은 실질 200~300px |
| 레고처럼 보임 | 재질에 `baseColor` + `emissive` 뿐 — **노멀맵이 없었다** |
| 리깅 조악 | `target_polycount: 30000` 을 내가 넣었다. 전신 3만이면 손에 몇백 개뿐이라 손가락이 뭉친다 |

### 멀티뷰가 노멀맵을 가져왔다
`multi-image-to-3d` 로 바꾸자 받은 맵이 달라졌다:
- 정면 1장: `base_color, emission`
- 멀티뷰: `base_color, metallic, roughness, **normal**, emission`

폴리곤도 54,244 → 296,316 (5.5배). 텍스처 예산도 768 → 2048 로 되돌렸다
(한 번에 한 명만 로드하므로 1인당 2MB 는 감당된다 — **얼굴이 주인공인 게임이다**).

### 함정: Meshy 리깅이 노멀맵을 떨어뜨린다
- 리깅 **전** `.mv.glb`: baseColor, emissive, normal, metallicRoughness
- 리깅 **후** `.mvrigged.glb`: baseColor, emissive 만

`scripts/restore-pbr.mjs` 로 리깅 전 파일에서 맵을 꺼내 다시 붙인다. 같은 UV 라 그대로 얹힌다.

### 내 코드의 버그
`mm.roughness = 0.56` 처럼 상수를 박고 있었다. glTF 에서 이 값은 **맵에 곱해지는 계수**다 —
맵이 있는데 0.56 을 넣으면 텍스처가 담은 재질 변화가 통째로 눌린다.
맵이 있으면 계수를 1 로 두도록 고쳤다. 노멀맵을 복원해 놓고 이걸 놓치면 헛수고다.

### TDZ 를 같은 파일에서 두 번 밟았다
`applyCam` 을 `tick()` 안에서 부르는데 선언이 뒤에 있었다. 앞서 `lastFrame` 으로 똑같이 당했다.
**`tick()` 이 참조하는 것은 전부 `tick()` 정의보다 앞에 선언한다** — 이제 그 자리에 주석으로 못 박았다.

### 버린 대안
- **카메라 드리프트로 입체감 보강**: 사용자가 "그런 게 아니라 생성부터 여러 시점" 이라고 잘랐다.
  드리프트는 시차 단서로 유효해서 남겼지만, **증상이 아니라 원인을 고치는 게 먼저**였다.

## ★ emissive — "조악해 보이는" 가장 큰 원인이었다

재질을 열어보니:

```
emissiveFactor : 1.00, 1.00, 1.00
emissiveTexture: 있음 (baseColor 와 **같은 이미지**)
```

**인물이 자기 알베도로 스스로 빛나고 있었다.** PBR 에서 최종 색은
`조명받은 baseColor + emissive` 이고 emissive 는 조명을 완전히 무시한다.
즉 화면에 보이던 것은 사실상 **평평한 스튜디오 조명이 구워진 원본 사진**이었고,
공들여 만든 흔들리는 등·그림자·노멀맵은 그 위에 겨우 얹히는 정도였다.

Meshy 의 기본 출력 방식이다 — 조명 없는 뷰어에서도 보이게 하려는 배려인데,
조명을 설계한 게임에서는 정확히 반대로 작동한다.

`mm.emissive.setScalar(0); mm.emissiveMap = null` 로 끄자 인물이 비로소 방의 조명을 받고,
노멀맵과 러프니스맵도 그제야 일을 시작했다.

**교훈**: 생성 도구의 출력을 그대로 믿지 말고 **재질 계수를 열어봐야 한다.**
텍스처 목록만 보고 "맵이 다 있으니 됐다" 고 넘어갔는데, 정작 문제는 계수에 있었다.
