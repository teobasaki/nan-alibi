# 005 — 심문 호출 파라미터: reasoning effort=none, 캐시는 포기

- 날짜: 2026-08-05
- 상태: 채택

## 맥락

Task 9(실연동)에서 첫 호출이 **3.1초**였다. 완료기준 D3(p95 ≤ 3.5초)에 아슬아슬하고
D2(첫 응답 ≤ 1.2초)는 불가능한 수치다. usage 를 보니 출력 86토큰 중 **45가 reasoning 토큰**이었다.

## 결정

1. `reasoning: { effort: 'none' }`
2. 모델 `gpt-5.6-terra`
3. **프롬프트 캐시는 포기한다** (아래 근거)
4. `prompt_cache_key` 는 남겨둔다 — 프리픽스가 길어지면 그때 자동으로 작동한다

## 근거 — 전부 실측

| 설정 | 지연 | 출력(추론) |
|---|---|---|
| terra 기본 | 2.95s | 100 (45) |
| terra effort=low | 2.12s | 118 (60) |
| **terra effort=none** | **1.74s** | **46 (0)** |
| luna effort=none | 1.83s | 55 (0) |

- **페르소나 연기에는 추론이 필요 없다.** 지식 시트가 이미 "무엇을 말할 수 있는가" 를 구조로 고정하므로,
  모델이 추가로 생각할 여지가 설계상 없다. 추론 토큰은 순수 낭비였다.
- luna 가 terra 보다 **오히려 느렸다** (1.83 vs 1.74). 싼 모델이 빠르다는 통념이 여기선 안 맞는다 —
  비용 강등 카드로 남기되 지연 개선용으로는 쓰지 않는다.
- 프로덕션 실측 12회: **1.35~2.71초, 재시도 0회, 폴백 0회.**

### 캐시를 포기하는 이유

OpenAI 캐시 최소 프리픽스는 **1,024 토큰**인데, 우리 페르소나 프리픽스는 **668자 ≈ 600토큰**,
턴 포함 전체 입력이 **666토큰**이다. 최소치에 못 미쳐 `cached_tokens` 가 계속 0이다.

**프리픽스를 억지로 늘리지 않는다.** 캐시를 켜려고 의미 없는 텍스트를 넣는 건 본말전도다:
- 비용상 무의미 — 캐시 없이도 판당 **약 $0.02** (입력 666×7 + 출력 ~100×7). 예산 $0.15 대비 7배 여유.
- 지연상 무의미 — 이미 1.7초로 예산 안이다.
- 오히려 손해 — 프리픽스가 길수록 입력 토큰이 늘고 모델이 산만해진다.

## 버린 대안

- **effort=low**: 2.12초. none 대비 0.4초를 더 쓰는데 페르소나 품질 차이가 관측되지 않았다.
- **프리픽스 패딩으로 1,024토큰 넘기기**: 위 근거대로 이득이 없고 비용·품질 양쪽에 손해다.
- **스트리밍**: 구조화 출력(JSON)은 부분 파싱이 까다롭다. 1.7초면 클라이언트 타이핑 연출로
  체감을 덮을 수 있다. 지연이 3초를 넘기 시작하면 재검토한다.
- **luna 로 강등**: 비용은 1/10 이지만 지연 이득이 없고 페르소나 표현력이 떨어질 위험이 있다. 비상용.

## 영향

- 완료기준 **C5(캐시 히트)를 폐기**하고 **C6(페르소나 감사)로 대체**한다 — 아래 참조.
- D2(첫 토큰 ≤1.2초)는 스트리밍 없이는 달성 불가 → **"응답 완료 ≤2.5초"** 로 재정의한다(실측 1.35~2.71).
- `npm run audit:persona` 로 8종 페르소나 감사를 수동 실행한다.

## 부수 결정 — C5 를 C6 으로 교체

원래 C5 는 "캐시 히트 확인" 이었다. 캐시를 안 쓰기로 했으므로 측정할 것이 없다.
대신 **C6: 8종 페르소나의 버릇이 실제 출력에 나타나고, 쌍별 문자 2-gram 유사도가 55% 미만** 으로 대체한다.

`dialogue` 스킬의 `voice-check.ts` 를 쓰려 했으나 **영어 전용이라 폐기했다** —
한국어에서 contraction/fragment/question 비율이 전부 무의미하고 `22:30` 을 단어로 토큰화한다.
그 스킬의 값어치는 SKILL.md 의 D1~D6 진단과 4요소 체크리스트에 있었고, 그건 페르소나 카드 작성에 이미 썼다.

**첫 실행 결과: 버릇 검출 8/8, 최대 유사도 21.4%(timid ↔ guilty).**
가장 비슷한 쌍이 `PERSONA_CONFLICTS` 에 이미 "동시 출현 금지" 로 박아둔 조합과 일치했다 — 설계 제약이 실측으로 확인됐다.
