# ADR 015 — improve-game 감사 6항목, 그리고 6번을 하지 않은 이유

## 감사 결과 49 / 65
`improve-game` 스킬은 Phaser/Play.fun 전제(`src/core/Constants.js`, EventBus, safe zone,
entity sizing)로 쓰여 있어 이 게임(DOM/TS)에는 그대로 적용되지 않는다.
해당 없는 항목은 빼고 13개 영역으로 채점했다. 최하위는 **오디오 1점(전무)** 과
**키보드 접근성 2점** 이었다.

## 1~5번 — 구현함
| # | 항목 | 무엇을 했나 |
|---|---|---|
| 1 | 키보드 포커스 | 재렌더 뒤 `data-fk` 로 같은 요소를 되찾는다. 사라진 요소면 같은 종류의 다음 것, 그것도 없으면 상단바 |
| 2 | 오디오 | `ui/sound.ts` — **파일 없이 WebAudio 합성.** 인장·해금·무반응·조회·결과 5종 + 음소거(기억됨) |
| 3 | 터치 타깃 | `@media (pointer: coarse)` 에서만 44px. 데스크톱 밀도는 그대로 |
| 4 | 화면 전환 | 오버레이 페이드, 서류 안착, **인장이 찍히는 모션**. `prefers-reduced-motion` 존중 |
| 5 | 판 기록 | `ui/records.ts` — localStorage 최고점·해결률. 브리핑에 목표로, 결과에 갱신으로 |

포커스는 **빠진 기능이 아니라 깨진 약속**이었다. `role="button"`·`tabIndex`·`aria-pressed` 를
일부러 붙여 키보드 플레이를 표방해 놓고, 정작 첫 행동 뒤엔 Tab 을 처음부터 다시 눌러야 했다.
브라우저에서 `activeElement === body` 로 실측 확인했다.

## 6번(DOM 부분 갱신) — **재고 나서 하지 않기로 했다**

사용자는 6번을 포함해 전부 승인했다. 그런데 착수 전에 실제 비용을 쟀다:

| 측정 | 값 |
|---|---|
| 전체 재렌더 1회 | **0.78ms** |
| `#app` 하위 노드 수 | **103개** |
| 60fps 프레임 예산 | 16.7ms |

**성능 문제가 존재하지 않는다.** 가상 DOM 도입은 `main.ts` 전면 재작성이고,
마감 이틀 전에 120개 테스트가 지키는 배선을 갈아엎는 위험을 감수할 근거가
측정값 어디에도 없다.

대신 재렌더가 실제로 만드는 결함 셋을 정확히 잡았다:
1. **포커스 소실** → 1번에서 해결
2. **스크롤 위치 초기화** → 재렌더 전후로 `.col` 스크롤을 복원
3. **인장 애니메이션 재생** → 4번을 넣자마자 생긴 회귀였다. 매 행동마다 기존 인장이
   전부 다시 찍혔다. `ui.stamped` 로 처음 찍힐 때만 `fresh` 클래스를 준다

즉 **6번이 노리던 사용자 체감은 전부 얻고, 재작성 위험만 뺐다.**

## 원칙
안 재고 갈아엎지 않는다. "전체 재렌더는 느리다" 는 그럴듯한 통념이고, 이 규모에서는
사실이 아니었다. 리팩터의 근거는 코드 냄새가 아니라 측정값이어야 한다.

## 덤으로 발견한 것 — 리뷰 루프의 판정 기준이 틀렸다
개선을 넣고 회귀 확인차 리뷰를 돌렸더니 12판 0건 → 5건 → 1건 → 4건이 나왔다.
**같은 빌드에서다.** 리뷰어는 LLM 이라 결정적이지 않다.

즉 앞선 "12판 0건 수렴" 선언은 **한 표본을 근거로 한 과잉 주장**이었다.
`scripts/review.mjs` 의 판정을 고쳤다 — 연속 `CLEAN_STREAK`(기본 3)회 무지적일 때만
수렴으로 친다. 한 번 0건이면 "이번 판은 지적 없음, 연속 1/3" 이라고만 말하고 계속 돌린다.

현재 상태는 수렴이 아니라 **정체(plateau)** 다: 12판당 0~5건이 오가고 blocker 는 0,
남은 지적은 전부 "코치를 더 세게 하라" 계열이다. 이건 결함 목록이 아니라 취향의 경계다.
