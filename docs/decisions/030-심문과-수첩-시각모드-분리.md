# 030 — 심문과 수첩의 시각 모드를 분리한다

- 날짜: 2026-08-10
- 상태: 채택

## 맥락 (어떤 문제·제약이 있었나)

UI 목업 정본은 심문을 네이비·차콜의 어두운 장면, 수첩을 크림 종이의 밝은 기록물로
정의하고 두 모드를 섞지 말라고 했다. 실제 구현은 심문도 펼친 수첩 컨테이너 `.nb`
안에 두었고, 파일 후반의 밝은 종이 변수와 `.nb .nb-page` 규칙이 심문까지 상속됐다.
그 결과 3D 인물은 작은 상단 뷰포트에 갇히고 화면 대부분이 빈 종이로 남았다.

## 결정

- 심문 중 루트에 `.nb.interview` 를 붙여 수첩의 색 변수·종이 배경·제본 그림자를
  명시적으로 끊는다.
- 심문은 왼쪽 용의자 레일 / 중앙 인물 무대 / 오른쪽 변화 큐의 3열을 유지하되,
  중앙 인물을 가슴 위 크롭으로 화면의 주인공으로 삼고 최근 질문·답변을 무대 하단에 겹친다.
- 색 의미는 청록=선택·새 기록, 주황=변화, 적색=확정된 모순으로 고정한다.
- 레퍼런스의 BEFORE/CURRENT 비교는 존재하지 않는 진술 번복으로 흉내 내지 않는다.
  실제 엔진이 가진 같은 시각의 본인 진술 / 객관 기록을 수첩 양면에 비교한다.

## 근거 (왜)

- 심문과 수첩은 플레이어의 목적과 밝기, 정보 밀도가 다른 화면이다. 같은 표면을
  공유하면 장면과 기록 양쪽의 위계가 약해진다.
- 현재 DOM 구조를 유지한 채 루트 상태 클래스에서 분리하면 3D 마운트·게임 엔진·
  수첩의 기존 기능을 건드리지 않고 시각 계약만 바로잡을 수 있다.
- 게임 상태에 없는 번복을 표시하지 않아 추리의 사실 계약을 보존한다.

## 버린 대안 (그리고 왜 버렸나)

- **심문 DOM을 `.nb` 밖으로 전면 재작성**: 마감 직전 3D 영속 호스트와 전체 재렌더
  경로를 흔드는 위험이 크다.
- **종이 테마를 전체 게임에서 제거**: 대조표와 수첩의 물성을 함께 잃는다.
- **레퍼런스처럼 진술 번복 데이터를 표시**: 엔진에 없는 상태를 UI가 지어내 추리를
  오염시킨다.
- **색만 어둡게 조정**: 인물 크기·빈 여백·대화 위계 문제는 남는다.

## 영향 (이 결정으로 바뀌는 것)

- `src/main.ts`: 심문 루트 상태 클래스, 대화 화자 라벨, 변화 큐, 실제 모순 수첩 비교.
- `src/style.css`: 심문 전용 팔레트·3열 비율·무대 오버레이·반응형 규칙.
- 엔진·사건 데이터·LLM 프롬프트·판정 규칙은 바뀌지 않는다.
