# 031 — GC-001 은 해금이 아니라 **가설을 증명한다** (조사 계층 신설)

- 날짜: 2026-08-27
- 상태: 채택
- 명세: [`docs/spec/GC-001-Hypothesis-중심-구현-명세-V0.2.md`](../spec/GC-001-Hypothesis-중심-구현-명세-V0.2.md)

## 맥락 (어떤 문제·제약이 있었나)

팀 QA 3-3-(5)(6)(7) 이 심문의 정보 획득과 게임 루프의 좁음을 지적했고, 그 지적이
**구현 명세 V0.2** 로 왔다. 명세는 방향 제안이 아니라 구현 기준이라고 못 박는다.

바꿀 것은 사건이 아니라 **알아내고 증명하는 방식**이다.

```
기존:  질문 → 정해진 진술 → Evidence 해금 → 특정 인물에게 제시 → … → 결정적 Evidence → 범인 판정
V0.2:  질문/조사 → Claim·Fact·Evidence → 비교 → 의문 → 가설 → 검증 → 근거 연결 → Proof → 입증
```

제약이 둘 있다.

1. **GC-001 의 Truth 는 한 글자도 바꾸지 않는다** (명세 §2). 범인 류나린, 21:16,
   고의적 직접 물리력, 인물별 실제 행동과 숨긴 사실, Evidence 의 객관적 내용, 타임라인.
2. **시드 사건 400개의 결정론을 깨면 안 된다.** `pool.json` 은 빌드 타임에 검증된
   사전 풀이고, `caseGen`·`solver`·`game` 의 출력이 바이트 단위로 같아야 게이트를 통과한다.
   V0.2 의 요구(Clue 상태·Intent·Proof)는 GC-001 에만 있는 데이터를 전제한다.

## 결정

**기존 엔진을 고치지 않고, GC-001 전용 「조사 계층(inquiry layer)」을 옆에 세운다.**

- 새 순수 모듈 `src/engine/inquiry.ts` — `Clue`(CLAIM/FACT/EVIDENCE) · `EvidenceState`
  (AVAILABLE/DISCOVERED/UNDERSTOOD) · `ClaimState`(6종) · `InquiryState` 와 그 리듀서.
- 사건 데이터 `src/data/gc001-inquiry.ts` — Fact(`F-*`) · Claim(`CLM-*`) · 지식 규칙 ·
  Investigation Question · Proof Proposition. **정본의 id 를 그대로 쓴다** (정본 §10·§23).
- `GameState` 는 건드리지 않는다. 조사 계층은 `GameState` 를 **읽기만** 하고,
  자기 상태를 따로 든다. 두 상태는 UI 가 나란히 들고 다닌다.
- 최종 판정: GC-001 은 `Proof Validator`(명제 기반), 시드 사건은 기존 `submit`(3축).
  같은 화면에서 갈라지는 것이 아니라 **사건이 자기 판정기를 고른다.**
- AI 는 표현만 한다. `Question Intent → Rule Engine → 허용 Claim/Fact → Persona AI` 순서로
  **말할 수 있는 범위를 코드가 먼저 정한다.** 불변식 1(진실을 AI 에 주지 않는다)은 그대로다 —
  오히려 좁아진다: 이제 그 인물의 claim 전체가 아니라 **이 질문에 허용된 claim 만** 나간다.

## 근거 (왜)

- **명세가 요구하는 것은 새 데이터 모델이고, 기존 모델은 그 자리에 남아야 한다.**
  `Trajectory`(5칸 궤적)는 400시드의 뼈대다. Claim 을 상태 있는 객체로 바꾸려면 그 뼈대를
  건드려야 하는데, 그러면 사전 검증 풀이 통째로 무효가 된다 — 대회 제출물의 근거가 사라진다.
- **한 사건만 새 루프를 쓰는 것이 명세의 실제 요구다.** 문서 제목이 「GC-001 Hypothesis
  중심」이다. 시드 사건은 매 판 다른 사건이라 Proof Proposition 을 손으로 쓸 수 없다.
- 조사 계층을 순수 함수로 떼어 두면 **헤드리스 테스트가 Acceptance Criteria 15개를 전부
  잰다.** UI·3D·서버가 닿지 않는 계층에서 판정이 끝나야 AC-14(조사 순서가 달라도 같은 Truth)
  같은 조건을 기계로 증명할 수 있다.

## 버린 대안

- **`GameState` 를 확장해 한 모델로 통일** — 400시드 결정론과 사전 검증 풀이 깨진다.
  게이트(`tests/pool.test.ts`·`batch.test.ts`)가 즉시 붉어지고, 그걸 통과시키려면 풀을
  다시 굽는 수밖에 없다. 사건 하나의 루프 변경이 다른 400개의 사건을 흔들 이유가 없다.
- **기존 `presentUnlocks` 사슬을 지우고 다시 짜기** — 명세 §37 은 "제거 또는 신규 플레이에서
  미사용" 이라고 적었다. 지우면 제1막 폴백 경로(3D 실패 시 기록철 흐름)와 시드 사건이 함께
  죽는다. **참조하지 않는 쪽**을 택한다: 사슬은 데이터에 남아 선택적 지름길이 되고,
  진행의 필수 경로에서는 빠진다 (AC-04·05·06).
- **Intent 분류를 LLM 에 맡기기** — 싸고 쉬운 길이지만, 그러면 "이 질문이 무엇을 묻는가" 를
  AI 가 판정한다. 그 판정이 곧 어떤 Claim 이 열리는지를 정하므로 **진행 조건을 AI 가 소유**하게
  된다 (명세 §35·금지 5 위반). 결정론 규칙으로 분류하고, 애매하면 애매한 채로 페르소나에게
  넘긴다 (명세 §12 — 의도 해석 실패도 정상 응답이며 질문 1회를 소모한다).
- **거짓말을 시스템이 표시하기** — 금지 4. 충돌 가능성은 `QUESTIONABLE` 까지만 올리고,
  `CHALLENGED` 로 가는 것은 플레이어의 행동이다.

## 결과 (무엇이 달라지나)

- GC-001 에서 심문의 성공 조건이 "새 Evidence" 가 아니게 된다. 일반 사실은 그냥 답하고
  (AC-11), 숨기는 것과 거짓말하는 것만 단계적으로 열린다.
- `REV-17-084`(E9) 는 유일한 정답 열쇠에서 **강한 지지 단서**로 내려온다. 발견하지 않아도
  권한·위치 경로(Proof Path B)로 입증할 수 있다 (AC-06).
- 최종 제출이 "범인 + 동기 + 도구" 에서 "범인 + 방식 + **근거 2~4개와 그 연결**" 로 바뀐다.
  판정은 어떤 Evidence 를 골랐는지가 아니라 **어떤 명제가 성립했는지**를 본다.
- 질문 예산 정책이 명세 §5 로 통일된다: 정상 응답이면 항상 1회 차감(잘못된 질문도 플레이어의
  선택이다), 시스템 오류면 차감하지 않는다. **기존의 "폴백이면 환불" 은 바뀐다** —
  폴백도 정상 응답이면 비용을 받는다 (AC-02·03).
