# ADR 027 — 갤러리 통합·실플레이 3건 수리에서 내린 세칙

- 날짜: 2026-08-10
- 상태: 채택 (구현 커밋 d7d349f · 4e6ca96)
- 관련: ADR 026(30초의 현장 세칙), 사용자 실플레이 피드백 3건

## 1. 갤러리는 통짜 이식이 아니라 "서관 홀만 무대"다

art_gallery.glb(23MB→1.8MB, 2048·webp·draco)는 2층 구조(서관 홀 y=-0.6 ·
동관 저층 -2.2 · 계단 x=10~13.6)다. 오프셋(+1.5,+0.6,0)으로 서관 홀 바닥을 y=0 에
맞추고, 놀이 구역(SCENE_ROOM)을 **벽 안쪽면과 계단 목전 사이**로 실측해 잡았다 —
바닥 판정(floorAt)을 굽지 않는 근거가 이것이다: 구역 전체가 연속 바닥임을
bbox 실측이 보장한다. 동쪽 경계만 보이는 벽이 없는데, 계단 낙하 방지의 통제선이다.

- 버린 대안: 동관·계단까지 개방 — floorAt·낙하 처리·조명 재설계가 마감일에 얹힌다.

## 2. 최적화는 `--join false` — 이름이 죽으면 천장을 못 숨긴다

기본 optimize 는 재질별로 메시를 합쳐 노드 이름을 지운다. 천장·스카이라이트·조명
레일을 이름으로 숨기는 탑다운 처리(경찰서 CEILING_HIDE 문법)가 통째로 죽어서,
join 만 끄고 다시 구웠다 (드로우콜 +9, 무시 가능).

## 3. 벽 격자 베이크에서 **걷는 면과 장식 몰딩을 제외**한다

probe-walkgrid 문법(모서리 래스터화, 몸통 띠 0.3~1.9m)으로 구운 첫 판에서
시작점이 6.5m² 에 갇혔다 — floor 의 단차 테두리와 corner(픽처레일 몰딩)가
띠에 걸려 **홀을 전폭으로 가로지르는 유령 벽**이 됐다. 브라우저 도달성 BFS 로
잡았고(마커 10개 전부 unreachable → 제외 후 10/10, 2,934칸), /floor|stairs|corner/
는 굽지 않는다. 갤러리 가구(의자·조각상·문)는 그대로 구워 장애물이 된다.

## 4. "순간이동" 의 원인 — 이동이 실시간을 안 탔다

이동·클립이 dt(0.05s 캡)만 타서, 프레임이 처지면 시계(elapsedMs, 실시간)와
어긋나며 뚝뚝 끊겨 보였다. 수리: simSec(실시간, 0.25s 캡)으로 이동·mixer 를 밀되
**충돌 검사는 0.05s 조각으로 나눠** 터널링을 막는다. 1초 초과 간격은 여전히 0
(탭 정지 = 일시정지, ADR 026 §4).

## 5. 대기는 클립, 급반전(turn180)은 기각

Breathing Idle 리타게팅 7종(run 파이프라인 동일)을 기본 상태로 얹고
집기/이동/대기를 weight 로 섞는다 — 걷기 0프레임 A포즈가 "리깅 안 돼 있다"의
정체였다. turn180 은 배선하지 않는다: 조향이 12rad/s 보간이라 클릭 이동마다
급반전 원샷이 오발된다 (ADR 026 §8 과 같은 판단, 파일은 남아 있다).

## 6. 증거품 표현 서열 — 실모델 > 빌보드 > 프리미티브

props/ev-<kind>.opt.glb 를 bbox 실측으로 0.85m(0.5m 급 × 과장 1.6배)에 정규화.
재질은 **마커 인스턴스마다 복제**한다 — 근접 흰 윤곽빛(emissive)이 프로토를
공유하는 이웃 마커에 새면 안 된다. 봉인은 잿빛 틴트 + 자물쇠. keycard 는 실모델이
없어 프리미티브가 받는다. crate.opt.glb 는 지형 소품의 옷이고 충돌은 여전히
SCENE_BOXES 가 정한다 (보이는 것과 막히는 것의 SSOT 분리 없음 원칙 유지).
