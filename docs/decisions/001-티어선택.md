# 001 — 프로젝트 티어를 light 로 선택

- 날짜: 2026-08-05
- 상태: 채택

## 맥락 (어떤 문제·제약이 있었나)

FIVE_ALIBIS는 NAN 2026 사전과제 제출물이고 마감이 2026-08-07 (가용 2인 × 약 2일).
루트 CLAUDE.md는 새 프로젝트에 `project-bootstrap` 발동을 요구한다.
그런데 이 프로젝트는 부트스트랩 **이전에** 이미 두 가지를 갖고 있었다:

1. 승인된 정본 기획서 (`NHN/기획/FIVE_ALIBIS_기획서_v1.md`) — game-blueprint 스킬 산출물.
   완료 기준·종이 시뮬레이션·AI 에이전트 설계서까지 확정됨.
2. 코드 스캐폴딩 (Task 1) — vite+ts+vitest, 배포 워크플로, Workers 스텁.

## 결정

**티어 = light.** `docs/{STATE,QUESTIONS,INDEX}.md` + `decisions/` + `journal/` + 훅 2겹만 얹고,
`docs/spec/` 은 만들지 않는다.

## 근거 (왜)

- **spec 계층이 이미 존재한다.** standard 가 요구하는 `spec/BRIEF.md`(CEO 5질문) → 모호도 게이트 →
  `SPEC.md` 의 역할을, game-blueprint 기획서가 **더 게임에 특화된 형태로** 이미 수행했다
  (완료 기준 A~E, 종이 시뮬레이션 4종, AI 에이전트 설계서). 같은 내용을 다른 서식으로 옮겨 적는 건
  마감 48시간짜리 프로젝트에서 순손실이다.
- **light 도 잃는 게 없다.** 티어와 무관한 불변량 — STATE(세이브), decisions(ADR), journal(히스토리),
  훅 2겹(주입+종료검사) — 은 light 도 전부 받는다. 티어가 가르는 건 `docs/spec/` **하나뿐**이다.
- 스킬의 추천 규칙("MVP·수일 → standard")과는 어긋나지만, 그 규칙은 **스펙이 없는 상태**를 전제한다.
  여기선 스펙이 이미 있고 승인까지 끝났다.
- 승격은 언제나 가능하고 강등은 없다 — 애매하면 낮은 티어.

## 버린 대안 (그리고 왜 버렸나) — 필수

- **standard**: `spec/BRIEF.md` + `SPEC.md` 를 강제한다. 기획서와 내용이 90% 겹치는 문서 2개가 생기고,
  그 순간 **정본이 둘**이 된다. 기획서와 SPEC이 갈라지면 어느 쪽이 진실인지 모르게 된다 — 이게 실제 비용.
- **full**: dual-spec(Opus/Codex 교차) + Discovery 파이프라인. 2일 마감에 파이프라인만으로 하루가 나간다.
- **부트스트랩 생략**: 루트 CLAUDE.md 위반이고, STATE 없는 프로젝트는 다음 세션에 고고학이 된다.
  실제로 2인 작업이라 STATE 부재의 비용이 혼자일 때보다 크다.
- **init.sh 를 nan-alibi 에 직접 실행**: 스크립트에 `[ -e "$DEST" ] → exit 1` 가드가 있어 불가능.
  임시 디렉토리에 생성 후 **기존 파일을 건너뛰며** 복사하는 방식으로 우회했다.

## 영향 (이 결정으로 바뀌는 것)

- `docs/spec/` 없음. 스펙 질문은 전부 정본 기획서로 라우팅된다 (STATE.md 목표 섹션에 경로 명시).
- 모호도 게이트를 거치지 않는다 — 대신 기획서 §6 완료 기준 A~E 가 그 역할을 한다.
- 훅 2겹이 붙었으므로 이후 세션은 STATE 주입을 자동으로 받고, 종료 시 STATE 갱신 여부를 검사받는다.
- 기획을 재작성하게 되면(MVP 미달 시) 그때 standard 승격을 재검토한다.
